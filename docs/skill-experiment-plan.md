# Skill自进化研究推进方案：基础实验、方向选择与算法完善

**状态：方案，尚未执行。** 本文按用户最新要求重写，取代上一版论文对照矩阵。
**无skill、无反馈一次生成的库与成绩只读复用，不再生成、不再评测，也不因迁移H20而重跑。**
当前工作是确定什么反馈和编辑能够推动skill继续改进，不是重新验证已有基线或提前补齐论文主表。
已有事实见[研究交接](research-handoff.md)，资产见[研究库目录](../src/mvagent/skills/skill_sets/research-20261022/README.md)。

## 1. 整体目标与阶段目标

最终目标是冻结模型权重与MVAgent框架，由系统根据合法经验自动发现、修订、选择和淘汰Global/Video skill，改善完整多视频问答的官方准确率。
推理时仍由现有Selector自动选卡，允许none，不依赖人工分配或额外优化模型。

接下来的研究依次回答四个问题：

1. **可改进性：**错误中是否存在skill能够修复的具体取证、委派或证据使用缺口？
2. **可选择与可执行性：**有效策略是否能由当前Selector输入识别，Actor是否真正执行了它？
3. **反馈可学习性：**给优化器怎样的角色公开证据，才能产生修复上述缺口的编辑，而非换措辞或重复失败？
4. **可积累性：**一次有用编辑能否进入短闭环，并在后续题目上保留净收益？

不预先把“增加跨轮记忆”“更长轨迹”或“更强optimizer”定为答案。代码确有跨轮信息丢失，但修完这一点是否提高准确率，仍需实验。
同样，skill已被选中、注入、改变动作，均不代表它获取了更有用的证据。

当前诊断从**已进化的非空父库476532…**继续，而不是重复空库起点。Global和Video分别研究，伙伴固定；Video研究不必等新的Global方向成功。
这验证的是从已有库继续改进，不等于已经证明从空库自动发现两个角色的skill。
长期的从空库过程仅能接续合法、完整且可匹配的历史起点证据；缺失时标明该路径暂不可复现，不自动补跑用户排除的条件。

## 2. 全局规则

| 范围 | 必须保持的规则 |
|---|---|
| 禁止重复的条件 | 不新增空库rollout，不调用无反馈一次生成，不重新测历史一次生成库；取消旧方案的两历史库各400题比较及基线重测预算。每次编辑后都检查实际启用库，删掉最后有效卡或关闭两角色skill的候选计入提案预算并标受限，不发rollout |
| 模型与框架 | 开发以9B为主；Actor/Selector权重、基础Prompt、动作接口及既定推理预算冻结，seed=0；不同时换模型、Prompt和skill |
| 角色边界 | Global看自己的问题、指令、报告和公开历史；Video仅看自己的instruction、同视频Memory、观察与报告；不互泄私有轨迹 |
| optimizer权限 | 逐题输入仅来自Train的目标角色公开投影；不给GT、评分点、题号、task代号、Cal/Gate逐题内容；失败类型不得从Gate错题提炼后送入optimizer |
| Skill机制 | `when_to_use`只用于检索/选择，`strategy`才注入Actor；Global整题、Video单次请求固定首次选择；不修改运行时选卡框架 |
| 编辑与对照 | 一个实验单元只改一个角色、一个主要假设；固定伙伴、父库和非目标字段。已有复合候选先测整库效应，不谎称单因素消融 |
| 正式接受 | 候选整库自然选卡、完整问答；Cal选优、Gate官方总分严格正增益。局部支持度、选中率、成本和步数不作为接受目标 |
| 证据与失败 | 原始rollout先保存；Judge/基础设施失败单列，不记零分。强制注入、离线查表、人工路由只能作诊断，不替代自然库成绩 |
| 数据与统计 | 只用CrossVid开发；CVBench/MVU不进入优化。分母、同题增损、来源相关性和历史复用公开，重复题次不算新独立样本 |
| 搜索预算 | 每单元有上限；无效、重复、noop均占提案名额，不免费重采；不能失败后临时加卡、换seed或扩模型矩阵 |

硬件变化只影响能否直接配对解释，不改变禁止重测的范围。旧H100无skill/一次生成分数保留为历史参照，不能直接减去新H20分数声称同协议收益。
新增父子比较使用同环境的**非空进化父库**。父库已有身份匹配结果则复用；若必须新测，明确计入预算，每个分区只测一次共享。
Video为空而Global保留476532，不是整套MVAgent无skill条件；反之不得将两角色均关闭的运行改名为“环境验证”绕过限制。
合法非空库的自然Selector仍允许none；不为避免某道题弃选而强行注入，也不把自然弃选题误当成额外安排的空库实验。

## 3. 从已有证据出发，而不是重做旧矩阵

| 已知事实 | 研究上真正还缺什么 |
|---|---|
| 正式8候选只有首Global接受；第二轮12个格式/direct候选零接受 | 哪种具体行为缺口可被编辑修复，而不是再比一次格式名字 |
| 64个案例位置仅29个不同Train题，两个Video首请求相同 | 案例曝光是否重复；后续提案是否看到了真正不同、有正反例的反馈 |
| 首接受卡删复核阶段后动作大变、答案大变，净分接近零 | 行为变化如何转化为有用信息，改善与损害为何抵消 |
| temporal自然选卡错过部分固定注入收益，强Selector也未稳定改善 | 当前可见输入能否区分该程序的受益者与受损者，而不是语义是否相关 |
| Cal40排序与后续面板出现反转，旧Gate部分task也仅4题 | 排名/接受对单题和来源组是否敏感；不能直接宣称已经测得误筛率 |
| Video报告均能传到Global，但局部没有GT | 是观察、报告支持、上游instruction还是下游使用出了问题；整题分数不是局部标签 |

已经做过事件格式、入口宽窄/长短、强Selector、Codex分配、自然/强制注入及泛化watch-first，不把这些重新列为全新前置实验。
新的入口干预必须来自一个具体、此前未检验的可观察边界或反馈缺失。
“错题watch救回47%”仍是未严格复现的历史线索；本轮不为它重跑空库或一次生成，也不把找回该实验设为所有研究的门槛。

## 4. 前置基础实验：每项都必须决定下一步

### R0：用已有结果定位主要损失环节

新增模型问答：**0**。给这一分析一个有限工作单元，建议半天封顶，不另造大型审计平台。

只读已有Train轨迹、已完成候选和已保存评分，产出一张按角色/候选组织的表：

| 环节 | 必须核对的内容 | 不能混淆的解释 |
|---|---|---|
| 选择 | 候选是否可用、是否选中、none与旧卡竞争 | 没选中不等于正文无效；选中不等于相对有益 |
| 注入与执行 | 正文是否进入实际请求；预期action、参数或报告变化是否发生 | 注入率与遵循率是不同分母 |
| 信息变化 | 是否取得新的、与instruction相关的可见内容；是否仅重述旧报告 | 文本不同不等于更真实，不能凭无局部GT的报告判断视觉事实正确 |
| 最终增损 | 同题改善/退步/同分及官方分差；与上述环节关联 | 相关不等于完整因果归因；被选子集不是随机分组 |
| 提案利用 | 实际发送了哪些案例、反馈和前次失败；是否重复同一假设 | 保存过历史文件不等于optimizer实际读过 |

完整审读少量Train案例，例如12个改善/退步/未执行/成功参考，记录原始事件出处。不按Gate错题组织给optimizer的新案例。
已有六个Video格式臂均完成，不能重新跑；原1776份Video raw未完整复核的部分优先只读核对，拿不到时明确证据等级。
旧raw不齐不阻塞R1：R1的非空父库Train运行会产生当前可用证据，缺失项不伪造。

另用已有逐题成绩做一次Cal排名/接受敏感性分析：按task与来源组重采样，观察排序是否容易改变；Gate仅用于报告级对照，不改历史接受、不向optimizer发送细节。
若只有汇总分，不能据此估计配对区间或误筛概率。这个结果只决定后续是否要扩大验证覆盖，不用来挑“本应接受”的历史赢家。

R0结束后必须写一个优先判断：**先修选择、先修执行、先修证据获取/传递，还是先降低筛选噪声**，并列一个会推翻该判断的观察。

### R1：测试两个已有但尚未测的机制候选

无需再调用生成API，不重新写一批手工卡。库文件和完整SHA在[资源目录](../src/mvagent/skills/skill_sets/research-20261022/README.md)。

| 条件 | 保持不变 | 预期行为 | 必须观察的负面可能 |
|---|---|---|---|
| P：非空父库`476532…` | Global原进化卡、Video空 | 共同起点 | 只作父子参照，不是重新测无skill |
| G：Global委派库`1275c1…` | 保留父Global卡，Video仍空 | 将对象/时间约定带入instruction；先求跨视频anchor再委派依赖；必要时联合watch | 多轮求anchor挤占取证；真实0秒/边界事件被错误怀疑；新卡抢走原卡的适用题 |
| V：Video可靠性库`229e74…` | Global逐字保持476532 | 不把未观察/看不清写成确认不存在；定向补看；报告只保留有支持的事实与未知 | 无效补看、过度否定已有观察、报告过度含糊，反而让Global失去可用信息 |

G增加了第二张Global卡，同时改变竞争关系和正文；V同时改变复查、观察与报告。它们是完整机制候选，**不是纯委派或纯报告措辞消融**。
先不拆成几十种组件组合。G、V分别与同一P比较，不将两张新卡合并，不因G中途得分改变V的伙伴。

**首个测量单元：**原冻结Train80，P/G/V各一份完整自然rollout，最多240题次；匹配的父库结果可以扣除。
优先完成一份候选与父库的80题对照便分析，不等整张矩阵，也不把20题的偶然正分当普遍规律。
查看干预是否按预期发生，同时报告完整Train增损。针对指令内的目标行为记录分母；实际采样信息缺失时标未知，不把计划FPS当实际FPS。

两份候选完成Train后，原则上均继续完整Cal40；Cal严格提高才进入Gate176，未过Gate不接受。不按Train总分高低临时增加一道候选筛选门。
只有协议/基础设施错误，或预声明目标行为在可触发请求中完全未发生时，才提前停止并标为诊断未测完；不得从未完成的分区推断准确率。
父库三分区新测至多296，两个候选各至多296，R1完整上限**888题次**；这是当前非空父库最坏情况下也要重测的上限。
旧Cal40仅用于这次有限的开发判定，不据一次通过宣称稳定收益。

### R2：只补一个能区分原因的干预

R1后最多追加**一个**自然候选修复，或一个强制路由诊断，不把下表各行全部运行。改动由Train证据决定，伙伴和非目标字段固定。

| R1实际观察 | 下一项唯一干预 | 结果决定什么 |
|---|---|---|
| 新卡未被选，且已有证据提示正文可能有用 | 固定正文，只修一个运行时可见的适用边界；确有必要时改用一次预声明强制注入诊断 | 强制有益、自然无益才继续研究入口；不能仅凭没选中责怪Selector |
| 选中、注入，但目标操作未发生 | 固定when_to_use，只把strategy改成可执行的动作、所需信息和停止条件 | 仍不执行时检查预算/消费者边界，不继续增加同义提醒 |
| 按预期执行，部分改善却损害其他情形 | 固定其余步骤，只补一个由当前可见信息支撑的前提或退出分支 | 能区分就收窄作用范围；不能区分则考虑把判断放进观察后的strategy分支 |
| 按预期执行，但没有净效用；观察本身反复错误 | 不追加措辞试验 | 暂停该行为假设，重新判断固定Actor/工具下文本skill是否有可修复空间 |
| 提案继续重复已展示的同类失败 | 留下成对编辑记录，进入R3验证是否需要历史反馈 | 不先建设长记忆系统 |

强制路由只有Train诊断身份，最多80题；不能按干预后的答案或GT分配卡，再称可部署Selector。
自然修复最多完整80/40/176＝296题次。R1＋R2基础包最大**1184题次**，没有无skill或一次生成新增条件。
若修复也失败，当前机制单元结束；不是马上切换更大模型或追加十种Prompt。

### R3：方向有依据后，检验进化是否利用了试错经验

只有出现重复同类失败编辑、且实际optimizer输入缺少先前试错证据时，才启动这一单元；机制有效但无此问题时跳过R3，直接用现有反馈流程作R4短迭代。
只对一个有依据的角色/机制做短闭环。两种条件**都读取Train反馈**，均从同一个非空进化父库开始：

- A：读取当前父库的角色公开轨迹和整题反馈。
- B：在相同当前证据之外，读取前次编辑造成的选择、行动、报告和整题增损记录。

两者的案例集合、当前证据、上下文上限与保留规则一致；A仍可看相同累计案例的当前父库参考，避免把“多看了题”误当历史编辑反馈价值。
先固定两臂完全相同的当前证据，再为B的历史记录预留固定预算，不允许历史挤掉当前事件；A不填无关文字凑长度。
报告实际token差，检验的是新增这些具体历史信息的效用，不称严格等长Prompt对照。
历史记录只含Train事实及编辑，不含Cal/Gate分数、拒绝理由或隐式评价摘要。

只做两轮、每轮一提案。第一轮在尚无历史时共用同一提案与完整评估，得到相同的第二轮父库；第二轮再分为A/B。
因此最多**3份新库**，不必跑两条重复第一轮的长链。每份仍完整Train/Cal评估，Cal提高才进入Gate；相同库按身份复用。
这是一项短链机制检验，不足以证明长期自进化；若第一提案无效/无新证据，该单元不免费换样重采。
第二轮每臂仅一次生成，反馈作用与生成随机性尚不能分离；即使B更好也只是继续研究的探索信号，不写成记忆消融已证明有效。

若R0确认旧Cal/Gate对少量题过于敏感，R3前一次冻结更均衡的面板，建议目标Train80/Cal120/Gate200。
须先用QA元数据验证来源组隔离可行性，不改历史清单、不按新候选结果挑补充题；不可行就记录瓶颈，不换group_id伪装隔离。
新面板上只测非空进化父子库，**不重新引入空库和一次生成**。这一步不阻塞前面的Train80机制测量。

预算按实际冻结规模计算：`3×(T+C+G)`，另加一次尚缺的非空父库`T+C+G`。
旧80/40/176下是最多888＋296＝1184题次；若用80/120/200则最多1200＋400＝1600题次，已有匹配结果扣除。
两个分支的实际token、案例覆盖和错误调用分别记录；不能只用“提案数一样”掩盖信息预算差异。

判断同时看两层：历史反馈是否让第二提案针对已观察到的失效点作修正；完整Cal/Gate是否出现净增量。
仅减少重复而未改善分数，可保留廉价去重/曝光管理，但不据此扩建复杂记忆或宣称新算法有效。
两者都无信号则回到具体可改进性问题，而不是继续扩历史长度。

### R4：只把经过验证的组件接入连续进化

形成一个有证据支持的默认反馈/编辑流程后，再跑最多4轮、每轮1候选的短搜索，不再并行一组方法名。
只有Global方向有信号就先固定Video；只有Video方向有信号，就固定Global476532继续Video。两者均有效时先Global后Video，伙伴更新后重新核对局部上下文，不能拼接旧下游报告。
后续接受仍按同一完整库Cal/Gate规则，允许没有新接受，不要求两个库都非空。

观察接受谱系是否继续改善、是否反复生成同一失败编辑、是否发生跨角色抵消。4轮后停止，列出全部拒绝和负结果；不以选中率提高代替主分。
预算上限`4×(T+C+G)`，加一次缺失的当前非空父库评估；不是每轮重新测父库。旧面板至多1184，新80/120/200至多1600，不含尚缺父库。

候选和方法冻结后，必要时只做**进化父库与后代库**在保留400题的扩大确认，共800题次；不重新测历史一次生成库。
400题存在来源重叠，仍是开发确认，不是盲Test。确认无增益就停止该版本扩展，不能按这批结果改卡后重新称确认。
论文外部算法、额外Actor和最终全量表留待稳定方向形成后单独制定，不是本轮自进化开发的前置任务。

## 5. Global与Video分别怎样完善

| 部分 | 有依据的研究对象 | optimizer需要的证据 | 不应做的事 |
|---|---|---|---|
| Global | 委派信息是否自包含、跨视频依赖是否先解决、watch/analyze是否针对具体缺口 | 问题中的可见约定、真实instruction、返回报告、行动差异、整题反馈 | 把完整原题无差别塞给Video；预设某个task必须watch；读取Video私有轨迹 |
| Video | instruction范围、目标观察覆盖、旧Memory复用、报告是否保留未知与支持边界 | 本次instruction、prior Memory、observe参数/结果、报告及弱整题反馈 | 将整题0/1复制给每个Video；另造“报告可信度”奖励；读取兄弟视频或Global隐藏内容 |
| 入口 | 当前可见输入能否区分策略的适用前提与明显反例 | Global的问题/视频列表，或Video的instruction；成对受益/受损Train经验 | 让首次Selector判断未来报告冲突；把自然选择率当效用 |
| 正文 | 可执行的动作、信息依赖、观察后分支与退出条件 | 策略是否实际改变action/参数、返回了什么信息、改善与损害 | 更长、更保守、更多复核一律视为更好 |

Video只有`video_id＋instruction＋prior_memory`一致才可作局部配对。即使Global库固定，前次Video报告不同也可能改变后续instruction；这些后续请求仍须标记上下文变化。
观察文本对报告的支持程度仅是定位/选例代理，不等于视频真值；报告更谨慎也不自动等于系统更准确。

对skill样式只保留待验证原则：入口依据当下可见信号；正文写明确程序并处理前提不满足；约束由实际消费者可执行；观察后的判断留在strategy。
这些是架构相容条件，不是已经证明的通用性能规律。R1/R2应给每条留下正例、反例与适用范围。

## 6. 算法功能按必要性分层完善

| 顺序 | 改动位置与能力 | 为什么现在需要 | 完成标准 |
|---|---|---|---|
| 进入进化CLI前，非R1前置 | `configs/`、`eval/skill_eval/run.py`及`algorithms/rolewise/optimizer.py`：显式非空起点、只读历史输入引用、禁止基线回补 | 算法本身硬编码空库，只改CLI不够 | 从已校验父库开始；每次编辑后检查禁测条件，合法缓存缺失时报错，不暗中补跑 |
| 需要跨运行复用时 | `eval/skill_eval/evaluator.py`：按身份校验既有评测引用 | 避免重复父库测量，且不混H100/H20结果 | 库、源码/协议、题目顺序、预处理、模型/Judge及评分身份可追溯；不复制JSON冒充缓存命中 |
| 下一次optimizer调用前 | `infra/trajectory.py`：完整角色投影、案例轮换与曝光记录 | 已发生重复案例和缺失差异信息 | 先投影再按完整事件取舍；保留失败/成功/未激活参考，实际optimizer输入能追溯 |
| R1先分析记录，进入R3前固化 | `infra/`：记录每次编辑假设及实际作用 | 需要区分选卡、执行和效用 | 编辑、卡片SHA、原事件、分区身份齐全；不把自动标签写成未验证事实 |
| 条件做 | `algorithms/rolewise/`：把有限历史提供给下一次提案 | 只有R3支持才作为默认机制 | 同时可关闭供单因素检验；Train之外的内容不进入记录 |
| 条件做 | `configs/`及评测层：更均衡验证覆盖、固定伙伴阶段 | 筛选噪声或角色耦合成为实际瓶颈时 | 事前冻结面板/伙伴，保持官方总分接受规则，不按结果调权重 |

不新建通用调度平台、向量记忆库、多父搜索池、训练router或局部奖励模型。已有JSON、哈希、BankSnapshot、角色投影、BatchExecutor和Judge继续复用。
R1已有固定库评测路径可用，不等待上表全部实现；先产出第一份父子Train测量，再完成下一项确实需要的改动。
配置代码在`src/skill_evolution/configs/`，共享能力在`infra/`，方法在`algorithms/`；数据与批量评测仍归`eval/`。

实现细节必须准确：`trajectory.examples()`现在会先把JSON首尾截断，不能把这个损坏输入再套进`format_feedback()`。
应从完整角色投影接入已有formatter，并记录完整事件省略情况；它是信息完整性修复，不是未经验证的精度贡献。
`last_train/last_edit`每轮重置、seed仅用attempt导致跨轮重复等问题应有小型回归检查，但测试通过不能写成进化有效。

每次新optimizer提示只做一次实际请求内容预览：角色边界、案例身份/数量、失败与成功参考、token预算、输出schema和截断标志。
发现具体格式错误就修并进入下一候选，不为假设中的边界无限增加前置检查。原始请求响应先留存，输出格式失败计入预算。

**当前公共CLI尚不具备非空父库导入和跨运行合法复用，直接fresh启动仍会运行空库。**
在这些能力补齐前，R1使用现有固定库评测路径；R3/R4不能直接照旧`evolve_skills.py`启动，也不能通过修改历史manifest绕过身份检查。
历史raw不在GitHub的事实仍需披露；只有库、分数和MD不足以重建optimizer的Train输入。

## 7. 每个单元的交付与停止规则

每项实验只需一份紧凑记录：问题与可证伪预测、冻结父子库/数据/协议、实际问答数、主分和配对增损、目标行为是否发生、下一动作。
Global选卡用题级分母，Video选卡用请求级，注入用planner调用级；不把三者混在一起算“使用率”。
CrossVid主分是十任务macro，CCQA内部按评分点加权；小面板与来源相关性需配对区间/敏感性分析，不把一次接受当稳定泛化。

- **未选中：**只有正文效用证据支持时研究入口，不盲目提高选中率。
- **未执行：**检查消费者是否看得到、程序是否可执行、预算是否容纳；不直接否定整个方向。
- **执行却无净效用：**暂停该机制，不靠增加重复观察或更长记忆掩盖失败。
- **只在已选子集上正差：**同时报告损害和未选范围，不能用有偏子集代替整库结果。
- **反馈没有改变下一提案：**先核实际输入，再决定曝光管理或R3；不直接升级更强模型。
- **Cal/Gate排序不稳：**固定扩大覆盖、减少候选；不能按Gate挑有利样本，也不回写旧接受。

先完成R0和R1的第一个父子Train单元。R2/R3/R4是由结果触发的后续投入，不是一口气提交的四套实验。
H20数量与角色分配由接手者机动安排；用实际小批次吞吐估时，不承诺固定卡数或小时数。
本方案没有安排新的无skill、无反馈一次生成、论文外部方法全矩阵或GPU任务；这些限制也适用于自动恢复与缓存缺失路径。
