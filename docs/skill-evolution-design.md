# MVAgent：免训练 Skill 自进化的当前设计

2026-10-21。固定模型权重、MVAgent架构、基础Prompt、工具、推理配置与评分，只修改Global/Video的skill库。
目标是提高完整多视频问答的官方总分；选中率、文字质量、动作变化和调用成本均不能替代这个目标。

当前最基础的问题是：**能否找到跨题目和来源仍有净效用的文本程序，以及选择时可见的信息能否预测它相对不用skill的收益？**
已测365尚无稳定超过terminal这一主动控制的增量，不等于正文相对none没有价值；当前语义Selector也未获得Train反事实效用反馈，不能据其失败判定入口不可学。
本文给出已实现的基线、实测约束和一个待验证的最小方法假设，不声称新方法已经有效。

最新分数与冻结来源见[机制探索结果](skill-exploration-results.md)；早期记录保留在[首测](skill-evolution-probe.md)、[手工诊断](manual-skill-results.md)、[探索方案](skill-exploration-study.md)及Git历史中。
正式4轮×2候选已完成，只有首轮Global更新被接受。同GLM无反馈一次生成对照、首接受库的27B/35B迁移及joint_compare补充365确认仍待完成；不能提前计为方法验证。

## 1. 冻结接口与信息边界

系统包含一个GlobalAgent与每视频一个VideoAgent；后者对Global是instruction→报告的黑盒。
Global通过`analyze_videos`下达各视频指令、通过`watch_videos`联合观看片段，或直接`answer`。
Video通过`observe`指定what、时间范围与FPS，正常`finish`须已有成功观察；同视频多次请求保留自己的Memory。
联合观看至少选择两个不同视频，每视频一个合法片段；所选片段共享单次帧容量，由runtime决定采样，不接受FPS参数。
Video的observe则对每个范围单独调用视觉模型，各范围有自己的帧上限；同一次动作给出一个计划FPS，runtime按各范围容量调整。

| 位置 | 实际可见内容 | 不可据此要求的判断 |
|---|---|---|
| Global首次Selector | 问题、视频ID/时长、候选ID与when_to_use | 未来报告是否冲突、尚未观察的证据是否充分 |
| Video每次请求Selector | 当前instruction、候选ID与when_to_use | 同视频Memory的内容、源时长、Global问题或其他视频内容 |
| Global Actor | 问题、视频信息、自己的公开action history与返回报告、选中strategy | Video内部观察轨迹或私有记忆 |
| Video Actor | instruction、源时长、同视频Memory、选中strategy | Global其他上下文、兄弟Video的轨迹或报告 |
| 优化器 | 目标角色的库与契约、Train角色公开投影、整题得分反馈 | GT、Judge评分点、task代号/题号、其他角色私有轨迹、Cal/Gate细节 |

检索日志中的query可以含history，**不等于Selector实际LLM输入含history**。查看选卡机制时须核实际messages，而非只看审计字段。
Global每题、Video每次请求最多选一张或none，并沿用该选择；观察后的条件只能放进已选`strategy`，不能等待另选一张卡。
none继续运行原MVAgent，不是拒答，也不是普遍不退化保证；一次弃选与基线同输入同输出的实测证据不能外推所有运行。

卡片保持schema v3：`meta={id, role, stages}`、`when_to_use`、`strategy`；stages为initial/evidence，两个文本字段及渲染正文分别受1200词上限约束。
只注入strategy，故执行前提、排除条件与不适用时的普通取证流程必须写在正文中，不能只写在入口。
按role/stage过滤后，候选不超过8张全部呈现；超过8张才使用BM25/embedding融合召回8张，再交Selector。
当前rolewise最多8张/角色，尚未验证大库召回损失；卡数上限不是配额或最优容量结论。

Observer不会自动收到skill。委派路径中Global规则须经instruction传到Video，再经`observe.what`传到视觉读取；证据经报告回到Global。联合观看路径则直接把watch instruction送给视觉模型，返回文字证据。
Video步数耗尽的强制总结只接收instruction/Memory，不自动接收规划skill；Global终止性answer保留原strategy。
完整契约见[运行时说明](../src/mvagent/skills/README.md)与[写卡规范](../src/skill_evolution/skill_specification.md)。

## 2. 已实现的两个基线

### 无反馈一次生成：one_shot

每角色一次生成，输入角色任务、当前Actor基础System、动作与预算契约；不加载真实题目、轨迹、成绩或旧库。
默认DeepSeek-Flash，每角色自主生成1–8张；`--max-cards`只限制上限。原始响应先保存再校验，完整成功后冻结库与部署配置。
新加的同GLM单Global卡对照使用同一优化模型配置、零样例、max_cards=1；它仍与反馈方法的Prompt/schema及累计搜索预算不同。
详见[一次生成说明](llm-skill-generation.md)；一张成功生成的卡不代表该生成分布已经测清。

### 角色轮换：rolewise

现有实现从两个空库开始，按配置轮换Global→Video；默认配置为2轮、每轮2候选，本次正式实验使用4轮×2候选。
每次仅对当前角色一张卡执行`add/revise/remove/noop`，其他卡与伙伴角色库不变；同轮试验始终基于已接受父代，不把上一失败编辑隐式累加。
流程已经包含同题配对Train、角色公开投影、竞争解释和条件策略Prompt，不能将它们重新命名为新增算法贡献。

1. 冻结源码、模型/推理配置、split与空库；获得完整Train/Cal/Gate基线。已有同协议、同身份基线按授权复用，不重复空库推理。
2. 从含目标角色经验的Train题中取公开视图，包含成功参考及未解决/变化案例；完全没有该角色轨迹则跳过，不虚构局部经验。
3. 优化器返回一项编辑及假设。先保存请求/响应，再校验Schema、角色、卡数、词数与编辑范围；格式失败消耗提案预算并保留。
4. 每个有效新库在相同Train完整自然运行，再在完整Cal自然运行；后一提案可读取前一试验编辑与同题Train反馈。
5. Cal只选严格高于父代的最高分候选；同分按既有稳定顺序，若均不提高则保留父代，不用成本或步数破平局。
6. 该候选完整自然运行Gate；仅当官方总分严格高于父代才接受，否则拒绝。Cal/Gate逐题内容不进入优化器。
7. 轮换到另一角色，保留所有候选、失败、拒绝及接受谱系；完成时输出已接受库，可能仍为空库。

Video的整题分数仅是下游弱反馈，不是局部正确率标签；只有instruction、video和先前Memory均一致时，才提供局部前后配对。
若上下文改变，现有投影显式标记，不把不同请求拼成局部因果对照。伙伴库改变后重新运行完整系统，不拼接旧报告代替新rollout。
正式候选始终按**完整库、自然选卡、完整问答**评估；强选、手工路由与离线查表均不能替代接受成绩。
自然与强选对同一道题可能执行不同策略，强选还可能绕过适用前提；两者估计的是不同部署干预，强选总体负差不能否定其适用子集，正差也不保证自然部署收益。

## 3. 当前证据约束了哪些判断

| 已测事实 | 当前含义与边界 |
|---|---|
| Train80固定temporal相对空库+11.19pp，joint_compare+9.00pp；更大365上，已完成策略尚无稳定优于终答一句控制的增量 | 存在小开发面板正差，但不能把它归为特定程序的可迁移能力；terminal对照也不能替代同协议空库 |
| 27B/35B Selector的12种入口/编号分配均低于最佳常量及各自频率匹配随机查表期望 | 更强模型改善部分原路由，但本次未获Train效用反馈的语义Selector仍未显示条件收益预测优势；查表是9B保存结果诊断，不是新混合系统E2E |
| 首接受Global删除Stage2–3后，296对选卡及实际Selector输入/输出全部相同；105个共同选中题动作参数全部改变，Gate差−0.0872pp | 正文确实影响行为，但净收益未稳定；删除同时改变内容和长度，未隔离单组件，也未证明等效 |
| 本地Video首卡自然239请求全部弃选；强选后实际注入并明显改变动作/答案，Train官方点差仍低于空库 | 不能凭零激活判正文无效，也不能默认修入口就能获益；按预声明规则停止该入口修订实验 |
| 正式8候选只有首Global通过Gate严格正差规则，其365自然结果未超过terminal控制 | 接受是程序判定，不等于统计显著或稳定泛化；后续候选均未超过父库Cal |
| 同请求同Judge出现过异分；有Video在19次可见错误反馈后仍重复无效时间范围 | 小差值需评分一致性补充分析；规则写入、反馈可见、实际利用与最终得分是不同层次 |

Global与Video组合已出现非加性；更短/更长、关系/宽泛入口、保守弃选都没有形成普遍优劣规律。
目前**没有证明局部编辑具有局部效应、特定风格更易被正确使用、初始问题足以预测逐题最佳卡，或自进化稳定优于强一次生成**。
用户历史“约47%恢复”来自E2E答对而MVAgent答错的筛选子集，当前未完成同清单同协议复现；它是动机，不是总体提升率。

## 4. 优先检验：固定正文下的效用入口

**假设：当正文保持不变时，仅用合法Train公开轨迹及真实相对得分改写入口，能让自然选卡更接近有益正文，而非只匹配方法语义。**
这与已完成的更强Selector诊断不同：后者只看到问题与原入口，没有收到Train效用反馈。
现有rolewise已允许入口和正文编辑并提供配对反馈；本试验只是把编辑对象限制为入口，隔离一个尚未测过的问题，不宣称新增通用算法。

本轮最后一项诊断已完成一次GLM提案并冻结候选`f14ba6f7…`；120题自然评估与原入口Cal40控制已提交，尚无完整对照成绩：

1. 固定已有三张concise Global卡的全部strategy与meta（源库`7c3f0aa4…`），Video空库、Actor、Selector和工具接口不变。
2. 从Train80已完成反事实表选取角色公开案例与整题得分；只给Global视图，不给GT、Judge评分点、task/题号、Video私有信息或Cal/Gate内容。终答得分不被解释为局部报告真伪标签。
3. 同一GLM只提案一次，输出三张卡的新when_to_use；校验正文与meta逐字不变后冻结完整库。入口只能使用首次Global选择可见的问题及视频ID/时长，不能依赖后到报告或历史。
4. 新库完整自然运行Train80与Cal40，不根据中途分数决定是否继续；全部report-only，不进Gate、不晋升、不回传提案，也不手改失败卡重试。只在原正式任务完成并释放后使用其8卡槽，维持既定截止。
5. Train同题比较原自然路由、最佳常量及频率匹配随机查表期望；报告真实选择、正文注入与实际E2E分数的对应关系。原三卡库缺少匹配Cal成绩，因此另用8卡并行补齐完全不改卡的自然Cal40；Cal主比较原入口与新入口，空库为已有次对照，不补造Cal逐卡反事实表。

这是三张入口的联合修改，不定位哪句入口导致某次选择；输出更频繁或语义更贴切均不能代替完整官方总分。
Train中的事后最佳卡不是部署时可见标签；优化器只能尝试提取初始输入的可迁移规律，不能把题号、任务代号或样例答案写回入口。
自然路由与固定常量估计不同部署效果，固定常量是强诊断参考，不替代完整自然库的正式接受。

| 观测 | 允许的解释与下一方向 |
|---|---|
| 入口改变但实际路由或成绩未改善 | 本次反馈、表示和预算未解决部署效用，不证明初始信息理论上不足 |
| 只在Train改善，Cal未保留或区间很宽 | 保留过拟合与小面板不确定性；不晋升、不追加近义入口寻找赢家 |
| 优于旧语义路由但未超过最佳常量/匹配频率期望 | 可能改善覆盖或卡频率，尚未显示有效的逐题效用分配 |
| Train与Cal均有正差 | 支持继续研究该机制，但不能由复用Train80与Cal40宣称稳定泛化或通用学习能力 |

**来源隔离、更大且事前冻结的完整确认仍是未来测量**；当前80/40不能改称独立Test，已复用365也不能重新包装为盲验证。
后续确认才检验入口学习是否在新来源上超过事前固定的最佳常量；无论结果如何，都不新增no-skill复测。

另一待验证方向是固定入口与伙伴，只修改一个有Train证据支持的行为组件。
它收窄搜索自由度，但没有自动增加因果信息；Stage2–3联合删除已显示行为变化与分区收益分化，不能据此断定小组件编辑优于现有rolewise。
若将来研究该方向，须同父代、同信息和同完整评估预算比较，不预设“正文先行”是最优顺序。
观察后条件仍只写入strategy；运行时不新增反思器、在线换卡、共享记忆或训练router。

## 5. 论文对照与消融

主问题是同一MVAgent上的skill增量；E2E与其他视频Agent作为系统背景，不能代替这一受控比较。

| 对照 | 固定内容与要回答的问题 |
|---|---|
| 同协议空库 | 复用已授权且身份一致的完整基线；测实际增量，不把历史协议差异算作skill收益 |
| 强LLM无反馈一次生成 | 同优化模型、信息契约及最大库容量；另做单卡容量匹配。当前单GLM单卡仅覆盖其中一格 |
| Train一次蒸馏 | 给一次固定Train公开经验后生成，不读候选运行反馈；区分经验输入与后续迭代 |
| 现有rolewise | 同父代、角色、例子权限、候选/完整rollout预算；检验组件限制是否带来新增价值 |
| GEPA/SkillOpt适配 | 尽量保持原提案/搜索机制，统一可编辑空间与评测；逐项披露对接口和信息权限的适配，不冒称完整复现 |
| 入口、正文与路由 | 固定一项只改另一项；最佳常量、none及频率匹配随机是诊断参考。离线期望须标明，部署结论需真实自然E2E |
| 角色与交互 | Global-only、Video-only、轮换及组合；冻结伙伴后再比较，检验收益是否可加与轮换是否必要 |
| 冻结迁移 | 不再编辑同一库，换9B/27B/35B消费者与独立来源；比较各模型自己的同协议基线 |

同预算至少计入全部提案（含无效/拒绝）、完整Actor问答次数与验证次数；同时报告优化器token、Actor调用与GPU小时。
这些是公平性与成本审计，不加入正确率接受目标。不能只对齐候选数而忽略不同例子量、搜索长度或评分调用。
同GLM也不自动等于同Prompt/schema；单次一次生成与多轮搜索的差值不能全部归因于反馈。
正式人类手写基线按用户决定不做；已授权的手工卡与Codex分配作为机制干预单列，不冒充自动进化产物或专家基准。

[SkillOpt](https://arxiv.org/html/2605.23904v1)提供有界文字更新与验证筛选，[GEPA](https://arxiv.org/abs/2507.19457)提供轨迹反思与候选搜索，均应作为实际算法对照而非只引用名称。
[MASPO](https://arxiv.org/html/2605.06623v1)提醒搭档改变会影响下游收益；本方案不移植其混合局部奖励或扩大角色信息权限。
[Video-RSI](https://arxiv.org/html/2609.37950v1)强调旧轨迹不能消除观察缺口；本方案不进化harness，不让优化器越权看视频，也不采用其成本联合目标。
当前是固定权重下的外部skill库优化，尚未证明优化模型自身的改进能力随轮次递归增强，不据此声称强RSI结论。

## 6. 数据、统计与接受协议

当前CrossVid Train80/Cal40/Gate176共296题，补充确认365题排除了这些题及声明来源组；它们合计661道**开发题**，不是661个独立来源。
365的抽样未按得分筛题，但后续候选选择已经参考其他开发结果，因此是自适应开发确认，不是盲Test。

- Train是唯一优化器逐题反馈来源；选例子时不用task桶，题号、参考答案及Judge评分点不进入Prompt。
- Cal用于完整自然库筛选；Gate只用于既定接受与报告。重复使用二者必须记录全部尝试，不能再称无偏留出测试。
- 最终Test须在库与方法冻结后使用，CVBench/MVU不进入本轮优化；披露其历史开发接触，不能靠改分区名称制造独立性。
- CrossVid主指标为十task等权macro，CCQA在task内部按评分点加权；局部子集贡献使用完整面板分母，不能拿缺任务子集macro冒充总体贡献。
- 报告同题差值、改善/退步/同分、分任务结果、配对区间及来源组敏感性区间；多次比较与来源相关性均须披露。
- 下阶段独立确认在看候选结果前固定有意义的最小增益与样本计划，按配对差异方差及来源组相关性估计所需规模；不以小样本正差替代功效分析。

Gate仍只看官方总分严格正差，不临时改成显著性、成本或逐题不退化门；接受与“稳定提升已获证明”是不同结论。
同请求Judge canonical仅是补充敏感性分析：完整Judge身份和prompt一致才复用参考分，保留原始主表，不回写旧分数或喂给优化器。
原始rollout先保存再评分；Judge/基础设施失败报错，不记零分。模型合法产生的错误答案、无效动作及正常工具拒绝分别记录，不能统称评分失败。
