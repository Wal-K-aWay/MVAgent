# Global 手工诊断卡：英文配置的完整中文镜像

对应 [`manual_global.json`](../src/skill_evolution/configs/manual_global.json)。2026-10-21，由本助手根据 Train 的 Global 公开视图手工设计，不是人类专家独立编写，也不是已验证有效的卡库。只读首测 `000-global/proposal-00` 与 `proposal-01` 请求中的 `train_examples`；未查看 Video 私有轨迹或 Cal/Gate 内容。卡片不包含示例答案、题号、数据集名称或固定时间。

每个方法包含 `concise`、`procedural` 两种正文，以及 `broad`、`relation`、`contrastive` 三种入口。两正文保留同一核心方法，较长版本细化条件与步骤；它们并非严格同义改写，因此实验是写作风格与操作细节组合的比较，不应只归因为长度。三种入口保持方法不变，依次增强可见结构和近邻边界。实验程序为卡片分配无语义 ID，不把 `key` 给 Selector。

## 1. `joint_compare`：联合视觉比较

### `strategies.concise`

对于跨视频视觉比较，把区分性的特征一起观察，不只依赖各自措辞不同的独立摘要。在 `watch_videos` 中明确视觉关系与相关视频 ID。每个视频使用一个合法的源时间片段，至少包含两个不同视频，不提供 `fps` 字段。相关时刻未知时，通过局部 `analyze_videos` 请求定位；目标持续可见时也可使用较宽覆盖。比较相对应的证据，除非给定同步关系，否则不能用相同时间戳代替对应关系。请求支持比较两侧的可见细节，不诱导预期答案。仅复核可能改变结论的遮挡或冲突特征。事实始终保留来源身份；比较得到支持后，按题目要求的格式回答。

### `strategies.procedural`

1. 识别题目要求比较的可见关系：共有或不同属性、对象身份、空间关系或执行细节。保留准确目标和限定条件。本流程适用于联合观察相关视频有帮助的关系，不要求每个局部事实都再联合观察。
2. 选择能展示目标的源时间片段。复用足够的公开锚点。题目给定相关区间时，保留识别对象所需的周边上下文。如果短事件尚未定位，用 `analyze_videos` 分别询问各相关视频的局部目标在哪里出现、那里能看见什么。每条指令必须能仅凭该视频回答。目标持续可见时可宽覆盖；长时间概览可能遗漏短暂的区分特征。
3. 调用 `watch_videos`：至少两个不同的视频 ID，每个 ID 一个位于时长范围内的片段，不提供 `fps` 字段。指令须点明所选 ID 与要比较的准确特征。请求各视频中的可见证据和歧义，不要求观察器确认某个选项。对应事件可以发生于不同源时间；只有同步关系已建立时，相同秒数才表示相同时刻。
4. 保留来源身份并比较返回细节。外观相似本身不证明是同一对象。缺少描述不证明不存在。如果某个歧义可能改变答案，用更窄的联合观察或局部请求针对它取证；不要自动重做整个调查。
5. 所求关系获得支持后，按题目规定格式提交答案。若达到运行时上限，给出证据最支持的判断，在 `reason` 中说明重要不确定性，不编造观察。

### `applicability.broad`

关于多个视频之间相似性、差异、身份或可见关系的问题；联合观察能够为答案提供共同的视觉依据。

### `applicability.relation`

所求答案依赖比较某个对象、特征、位置或动作在至少两个视频中的呈现。本方法联合检查对应片段，以相同的视觉区分标准比较两侧。相关时刻可以仍待定位。

### `applicability.contrastive`

主要问题要求找出共有或区分性的视觉特征、跨视角身份或空间关系，联合比较至少两个视频有帮助。本方法使用对应片段与共同视觉判据。它不是统计有多少视频满足独立可观察条件、或依据参考事件寻找目标区间的首要方法；这些情况需要谓词聚合或时间映射。

## 2. `shared_predicate`：共同判据与量词核对

### `strategies.concise`

对于组合多个视频中可独立核验事实的问题，保留准确谓词、限定条件与所求量词。使用 `analyze_videos`，向每个相关视频提供相同的局部判据；不要把具体动作换成更宽泛的相关活动。请求决定性的可见证据，并区分已经执行、未观察到和不确定。错误执行须有动作发生及指定错误的证据，不能仅凭该动作缺失认定。按来源组合报告，把全部、恰好或任意等量词应用到题目指定的实体。报告替换判据或留下会改变结果的缺口时，提出聚焦的后续问题；不要强迫证据符合预期选项。按所求格式提交证据最支持的答案，在 `reason` 中保留重要限制。

### `strategies.procedural`

1. 提取各视频中需要核对的准确条件，以及最终跨视频执行的操作。保留合取、否定、时间限定，并明确题目统计视频、对象还是事件出现次数。相关动作不能替代指定动作。比较各视频的局部流程时，每个来源使用相同的比较维度。
2. 用 `analyze_videos` 发送自包含的局部指令。在每条指令中说明同一判据及相关定义，请求支持或限制判断的可见证据。VideoAgent 无法比较它看不到的其他视频。正确性属于谓词时，询问实际发生什么动作、哪项观察支持错误类别；不要把动作未发生等同于错误执行，也不要凭常识虚构理想操作流程。
3. 组合公开报告，每项事实保留所属视频。区分证据支持的存在、证据支持的不存在和未解决的证据。报告遗漏或含糊的“没看到”不自动等同于充分覆盖的否定。检查报告回答的是原始谓词，而非更容易的相邻问题。
4. 对有证据支持的局部发现应用题目的准确量词。如果可疑发现可能改变符合条件的集合或计数，向该视频提出关于缺失区别的聚焦、非诱导后续问题。如果问题需要跨来源比较视觉细节，用 `watch_videos`，选择至少两个相关视频，每个视频一个合法片段，并给出准确的共同判据；不提供 `fps` 字段。不要通过改写问题或假定建议的选项为真来修补矛盾。
5. 证据支持所求组合后，按题目格式回答；文字比较保留来源标签。达到运行时上限时，提交证据最支持的非空答案，并在 `reason` 中保留实质不确定性；不复制 Schema 占位文本，也不要求无限验证。

### `applicability.broad`

询问哪些视频或动作满足条件、有多少满足、共有何种内容、或局部可观察流程有何差异的多视频问题。

### `applicability.relation`

问题可通过在每个视频中独立检查同一指定条件或比较维度，再组合局部发现来回答。所求结果可能是全部、任意、恰好、计数、符合条件的子集，或所得局部事实的比较。

### `applicability.contrastive`

主要结果在同一明确条件或比较维度下组合各视频判断，例如哪些视频符合条件、所有视频共有何种内容、或局部流程有何不同。每个判断都可以在单个视频中独立观察。排除凭外观跨视角匹配对象、定位同步时刻、依据参考事件找到目标时间戳的任务；这些任务的决定性证据是跨来源关系或时间关系，而非独立谓词聚合。

## 3. `temporal_anchor`：时间锚点与状态映射

### `strategies.concise`

对于跨视频时间关系，分开锚点事件、它的源时间，以及所求目标状态或区间。先取得锚点的可见身份、动作和相关前后状态，再使用它。把已返回的参考事实传入之后的目标指令；并发 VideoAgent 调用不能共享新报告。只有同步关系明确时才使用相同时间戳。对等价步骤，匹配功能与状态变化，再核实目标两端边界；绝不复制参考时长。对缺失中段或排序问题，观察相邻的已提供状态并推断过渡，不能声称看到了缺失片段。粗略锚点的不确定性可能改变答案时，细化定位。联合观察至少包含两个视频和合法局部片段，不提供 `fps`。依据受支持的证据按要求格式回答。

### `strategies.procedural`

1. 识别问题中的时间依赖：同步锚点与目标状态、另一视频中的等价事件，或给定片段间的过渡。分开事件身份、源视频秒数和推断的先后关系。各输入视频有自己的时间起点；其时长不能揭示未提供片段的位置。
2. 获取锚点证据。对给定参考区间，请该视频的 Agent 描述相关动作、功能及其前后状态。对带标签的追踪对象，保留标签初始化规则以及准确事件条件，例如首次平齐或完全消失。对开头/结尾或排序任务，先观察给定片段的相关边界状态，再推断衔接变化。
3. 只传递已返回的证据。如果目标搜索依赖参考描述，在之后的 `analyze_videos` 动作中把该描述放进自包含的目标指令。匹配所求功能或因果关系，而非表面相同的动词。不要要求并发调用的 Agent 使用彼此尚未返回的报告。
4. 解决所求时间结果。对明确同步的视角，在已确定的锚点时刻观察目标状态；锚点是较宽区间且目标可能在其内变化时，细化锚点。对等价的目标步骤，请求开始与结束两端时间及各边界的状态转变证据。不要依据参考片段时长或通常流程用时推断结束位置。对缺失片段，选择兼容已观察两端的过渡，并明确它是推断而非观察。
5. 关系需要联合核验时，使用 `watch_videos`：至少两个不同 ID，每个 ID 一个合法的源时间片段，保留足够周边上下文，不提供 `fps` 字段。决定性的时间区别获得支持后停止取证。保留题目要求的答案格式；达到运行时上限时，给出证据最支持的判断，不编造时间戳或未观察事件。

### `applicability.broad`

关于事件何时发生、对应步骤、同步状态、事件顺序、或前后片段如何衔接的多视频问题。

### `applicability.relation`

所求答案把一个视频中的事件或状态，与另一个视频中的时间、对应动作或状态变化联系起来。题目提供参考区间、由事件定义的时刻、明确同步关系，或需要解决时间关系的较早/较晚片段。

### `applicability.contrastive`

主要结果需要时间映射：依据参考事件找到等价目标区间、在事件定义的时刻读取另一个同步视角、排列已观察状态变化的先后，或推断已提供前后片段之间的缺口。时间对答案不可或缺。排除时间戳只是可选支持证据的普通特征比较或逐视频条件检查。

## 设计依据与可检验预期

Train 公开视图出现了以下行为：局部指令把细粒度动作改成较宽动作；报告混淆“未发生”与“错误执行”；量词与报告不一致时猜测或复制答案占位文本；用参考片段时长猜目标区间终点；宽泛同步锚点未经核验便用于终答；没有观察给定片段就猜缺失中间。也存在得分提高但证据仍可疑的案例，以及选卡后退化的案例，因此不能把单条轨迹解释当因果结论。

可检验预期：联合比较提高真正依赖共同视觉判据的问题，但可能损害可分解任务；共同判据减少语义偏移和量词合成错误，但证据不足时仍可能失败；时间锚点减少不受支持的边界猜测，但更长的指令可能分散注意力。结构化入口可能减少跨方法误选，排除条件也可能导致漏选；更高选择率不代表更高准确率。这些均须完整 rollout 与官方评分检验，不能由此文档宣称收益。
