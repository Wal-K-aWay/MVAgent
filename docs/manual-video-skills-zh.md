# Video 手工设计诊断卡：中文镜像

英文资源：[manual_video.json](../src/skill_evolution/configs/manual_video.json)。本批由助手结合 Train 局部轨迹手工设计，不是人类领域专家编写，也不是已接受的进化结果。每种方法包含两种正文（`concise`、`procedural`）和三种入口（`broad`、`relation`、`contrastive`）；实验组装器分别组合，入口实验保持正文一致，正文实验保持入口一致。两个版本的核心意图相同，但步骤版增加条件和细节，因此其效果差异不能单独归因于长度。

设计只读取 Video 自己的 Train 视图：`checks4/role_sampling_smoke/request.json` 六例，以及 `probe/evolution/rounds/001-video/proposal-00/request.json` 三例，后者与前者有重叠，不是九道独立题。两处都位于 Modal `devbox/skill_evolution_20261021/`。未读取 Global 问题、其他视频内容或 Cal/Gate 逐题信息。整题得分不能当作局部报告正确率。

已观察到的可行动缺口：一条含多个判据的请求只得到笼统“操作正确”，报告却扩展为全部指定操作均正确；一条要求时间区间的请求在 `observe.what` 中漏掉时间要求，报告只保留过程叙述；后续请求明确要求起止时间，但观察仅给出起点，结束报告仍未指出终点缺失。也有包含多个判据的请求通过一次观察给出足够结果，不能因此规定所有请求必须反复观察。以上是文本轨迹中的契约缺口，不是经过视频复核的视觉事实错误，也不能证明它们造成整题错误。

Selector 只收到本次 `instruction`，入口不能依赖时长、Memory 或未来观察；Actor 执行时可使用这些局部信息。`finish` 仍须已有可用同视频观察（允许来自之前请求）；策略不依赖强制总结读取卡片。所有结论限于本视频，不指导选择跨视频答案。事件的时间证据可报告，但内部观察范围、FPS、工具过程不可写入总结。

## criterion_evidence：逐项判据与证据

预期行为：保留每项判据，避免把笼统结论或未提及事项扩展成确定结论；只针对可能改变报告的证据缺口补看。风险是判据过多导致正文冗长，或对本已充分的观察过度保守。是否改善整题准确率必须实测。

### concise 完整镜像

当指令要求判断列出的条件、动作或属性中哪些成立时，分别保留每项判据及其限定。复用相关的同视频 Memory。在 `observe.what` 中要求每个未解决判据的可见证据，而不是一个总判决。选择能呈现这些事实的源区间和 FPS；观察中漏掉的项目属于未解决，不能当作不存在。如果观察只说所有操作都正确，或只给一般叙述，在进一步观察可能解决问题时检查缺失的决定性事实。已有充分证据时不要重复检查。有可用观察后，`finish` 给出简洁的逐项说明：已支持的判断、决定性可见证据及未解决的限制。不要提高暂定识别的确定性，不要凭熟悉的流程补全未观察步骤，不要决定跨视频比较。

### procedural 完整镜像

当当前指令要求判断本视频中哪些指定条件、动作、物体或属性得到支持时使用此流程。保留要求的限定和关系；一般主题描述不需要人为增加检查清单。

1. 确定指令中的不同局部判据。检查同视频 Memory 中分别支持各项的证据。先前查看过一个区间不意味着已观察到每个要求的细节。在推理中区分有支持、有相反证据和未解决的判断，不增加输出字段或新记忆对象。
2. 对未解决判据，用 `observe.what` 提出一个连贯的视觉问题，保留必要区别并要求决定性可见证据。判断某步骤是否错误时，询问可见动作、前后状态以及什么支持所述错误类型，不要只要求笼统的对错结论。指令提供标准时沿用标准，不虚构隐藏的参考流程。
3. 选择视频时长内有序、互不重叠的源区间。相关活动尚未定位时可用广泛覆盖，有已有锚点时复用锚点。按所需细节选择 FPS。观察文字未提到某项或覆盖稀疏都不能证明不存在。若证据笼统、模糊或不完整，针对可能改变报告的未解决区别取证。已得到支持的判断不必再次观察。
4. 已有可用同视频观察后，`finish` 给出简洁、独立可读且回应每项要求的说明。陈述已支持的判断及其可见依据，指出仍未解决的判据。保留身份、顺序、覆盖范围的不确定性，不用常识填补。只有相关且已观察到时才报告事件时间，不透露内部观察范围、FPS 或计划。仅报告本视频证据，不选择跨视频答案。

### applicability 完整镜像

- `broad`：检查单个视频中要求的动作、物体、属性或步骤，报告哪些条件有可见证据支持。
- `relation`：指令询问多个指定动作、属性或条件中哪些成立，或询问某个动作是否满足明确限定。用可见证据分别回应各项局部判据，区分缺失证据与否定判断。
- `contrastive`：指令要求对指定备选项或明确的动作/物体条件作出局部判断，且每项判据需要独立证据时使用。不要用于无约束的主题总结，或主要要求事件起止时间、时间顺序的任务；仅提到多个物体并不意味着这是逐项检查任务。

## event_boundaries：事件边界与局部顺序

预期行为：把指令要求的起点、终点和顺序传入视觉问题；必要时用已有锚点细看缺失边界；报告未解决端点。风险是对只要粗粒度顺序的请求过度细化，或粗略观察产生错误锚点后继续围绕它检查。是否提高分数需要完整问答检验。

### concise 完整镜像

当指令要求事件时间或顺序时，确定准确动作，区分其开始、持续、完成和附近相似活动。复用同视频 Memory 中的锚点，不把未支持的端点当作事实。在 `observe.what` 中明确要求所需源视频秒数的起点、终点或顺序证据。事件尚未定位时先广泛覆盖，然后以周围上下文和合适 FPS 检查仍不确定的边界。裁剪边缘或第一个采样到的出现时刻不自动等于事件边界。若只支持一个端点，在可行时寻找缺失端点，而不是再作一次整段视频叙述。有可用观察后，`finish` 报告已支持的时间或顺序，标明近似边界和缺失端点。不要推断与其他视频同步。

### procedural 完整镜像

当局部指令要求定位事件、界定其持续区间或确定指定事件顺序时使用此流程。保留所要求的动作和物体。不要把识别或一般主题任务替换成不必要的时间戳细化。

1. 确定指令实际需要哪些时间事实：开始、完成、区间、多次发生或相对顺序。读取同视频 Memory 中相关事件描述和锚点。先前覆盖但没有明确时间证据不能确定端点，近似起点也不能给出持续时间。
2. 如果事件尚未定位，用足以定位的源范围执行 `observe`。在 `what` 中明确要求所需源视频秒数，以及识别该事件的可见动作。询问区分目标与相邻准备、重复或后续活动所需的细节。选择合法、有序、不重叠的 `where` 区间和适合动作时间尺度的 FPS。
3. 如果返回证据仍无法确定必要边界或顺序，利用已有锚点，在其前后保留上下文检查该不确定性。较短的相关区间可能比再次整体总结更清楚地保留短暂转变。根据观察锚点和实际时长选范围，不编造固定位置，不要求统一 FPS。区间边界、第一个采样帧或最后一次提及本身都不是事件边界。判断顺序时确认可见的先后证据，不假设熟悉的流程。
4. 可用观察已建立所需事实时 `finish`。报告已支持的事件区间或顺序及简洁识别证据；采样有限时保留近似精度。某端点仍未知时说明哪些部分已支持、哪些仍未解决，不制造完整区间。按要求报告事件时间，不报告内部观察范围、FPS 或工具细节。本视频局部时间不证明不同视频间的同步或顺序。

### applicability 完整镜像

- `broad`：定位并描述单个视频中指定事件何时发生，包括其持续区间或在动作序列中的位置。
- `relation`：指令要求的结果包括事件起止秒数、时间区间，或本视频中事件的明确先后关系。定位事件，区分所需时间边界或状态转变与附近活动。
- `contrastive`：主要局部交付是事件区间、起止边界或指定事件顺序时使用。事件不必已经定位。排除简单存在性检查和未要求时间关系的一般过程描述；要求描述步骤并不自动要求精确端点。
