# 手工设计 Skill 的机制检验

目标是检验策略文本和自动选卡是否能提高冻结 MVAgent 的准确率，不预设正结果，也不把所有失败归因于生成器。卡片由研究助手根据 Train 公开轨迹设计，不称为人类专家标注。Global 和 Video 的输入边界分别保持不变。

## 预先固定的比较

1. 用现有 Train80 中每类前两题组成 Train20。包括空库、逐张固定注入，以及完整角色库自动选卡。固定注入使用运行时已有 static 模式，注入正文与动态选中后的正文完全一致，仅用于诊断。
2. Global 三种策略：直接共同观察比较、保持同一判定标准、基于事件确定时间。Video 两种策略：保留逐项证据、获取事件边界。每种均有简短版与步骤版；两者内容详细程度也不同，因此不能将差异单独归因于长度。
3. Selector 固定正文，比较宽泛描述、关系描述、带排除条件描述，并交换编号顺序。使用真实 Selector Prompt 与模型。选中率、弃选率、编号敏感性分别报告；高选中率不等于选得正确。
4. 按 Train 结果选择至多两套自然选卡库，在现有 Cal40 上比较。冻结其中一套后，优先使用新准备的、与当前开发划分来源组隔离的 Gate200 做确认。元数据准备发现 NC 仅有 12 题、PI 仅有 4 题满足该隔离条件，因此在查看本轮效果前冻结确认集为 176 题：其余八类各 20 题。仍按十任务等权 macro 聚合，不通过复制题目或放松来源边界凑齐 200 题。Cal 与 Gate 的题目细节不提供给卡片作者。

## 判断口径

主指标为 CrossVid 十任务 macro，CCQA 按官方知识点权重聚合。报告有效样本数、每题配对收益/损失、分任务成绩及固定种子的分层 bootstrap 区间；探索性多臂筛选的 Train 最优值不能当作独立确认效果。最终自然选择的整库结果才用于机制有效性的主张，固定注入结果用于定位策略正文与选择之间的差距。

首次35B诊断最多使用两组 H100:8，Actor 为 Qwen3.5-35B-A3B，沿用已验收配置和官方 Judge。后续9B主实验见下文。每组七个 Actor 副本与一个 Judge，原有 48 H100 测试保持独立。每个运行保存源码、配置、库哈希、原始轨迹与评分；结果留在 Modal runs volume。

复用历史空库轨迹必须核对模型、Actor 源码、输入与协议，并保存来源和原始哈希；不将不兼容协议拼接为同一对照。若同一答案在独立 Judge 副本出现差异，分析采用预先固定的来源优先顺序统一相同评分请求，保留并报告原始差异，不择优取分。

## 解释结果

- 固定注入提升而自然选择不提升：提示选卡遗漏、误选或库内竞争，继续定位选择问题。
- 两者都提升且独立确认有效：支持存在有用策略及当前选择接口能利用它，但不能证明未来进化算法有效。
- 固定注入也不提升：当前卡片、任务适配或注入方式仍无充分支持；不能写成“仅生成算法不好”。
- 只在开发集提升或少量题改善：作为探索性证据保留，需要独立确认。

## 基于 Train 的一次补充检验

首轮简短自然库测得 Global 35.71%、Video 34.69%，低于同题空库44.69%。轨迹中出现 joint_compare 被选中却整题没有 watch 的情况：旧卡允许先委派，因此不能用其结果代替严格 watch-first 的检验。查看任何本轮 Cal/Gate 结果之前，固定增加[直接联合观看优先卡](manual-watch-first-skills-zh.md)的 Train20 固定注入/自然选择各一臂；它改变首个取证动作和原题语义传递方式，不修改原15臂。此为一次明确记录的 Train 开发迭代，不是新的独立确认。

## 扩样本与 9B 主实验

用户指出每类两题波动过大，并要求用更快的 9B 作为主模型。因此35B原冻结诊断矩阵收尾后停止，不再扩大35B或进入其Cal；保留其全部正负结果。新的主实验使用Qwen3.5-9B，Actor与Selector同模型，官方Judge不变；不得将35B答案或分数补入9B对照。35B初步观察只用于设计固定策略，不是9B的测试结果。

9B使用原Train80（每类8题），同时评估空库、Global短/长自然库、Video短/长自然库和watch-first自然库，共6×80=480次完整自然运行。十张原始固定卡及watch-first卡各在同一Train20上做强选诊断，共220次；强选20题不作为稳健全体收益证明。总计划700次完整问答，实际完成数另记。Selector输入从9B自己的空库Train80公开输入与首次Video instruction提取，比较三种描述与两种编号，统计样本数以实际调用记录为准。

80/40/176清单SHA256为 `794a66996f1e12fceea9e6c7f12fcd6416fb4704c6a96e573e715ae7a35b1a21`。原Train20包含于Train80；扩大样本不是按得分挑题。每个普通样本对Train80宏观总分的影响约1.25个百分点，比Train20的5个百分点更小，但仍须报告配对区间及来源组相关性。两个自然候选最多进入Cal，只有候选有值得确认的收益时再使用冻结Gate；不能把筛选出的Train赢家当独立效果。

9B结果位于原runs根的 `nineb/`，35B诊断保留于 `retry/`。这一初始阶段新增GPU最多16 H100，新节点等待对应35B节点释放后接管；追加手动路由后的总预算见下节。9B上的skill收益不推出35B/27B收益更大，迁移须固定同一卡库另测。

## Codex手动选择与保守弃选对照

用户追加要求后，增加Global逐题分配诊断：相同Train80、相同卡库与9B Actor，对比原9B Selector、Codex选择和更保守的Codex选择。Global简短与步骤正文分别测试；Codex的分配在任何新手动路由rollout之前冻结，同一分配用于两版正文。

隔离的Codex路由代理只接收原Selector System及可见User输入：问题、视频标识/时长、候选编号和when_to_use。不给GT、任务代号、Actor答案、轨迹、逐卡得分或strategy正文；不用事后逐题最高分决定分配。标准版选择语义最直接且有输入支持的方法，也可弃选。保守版只保留标准版中主操作及关键关系明确的选择，否则弃选；不能改为另一张卡。理由和两份映射写入Modal并保存输入/映射哈希，理由不注入Actor。

运行时复用已有static模式，按分配分组调用原生评测器，每组独立冻结配置、输入与源码；弃选只关闭Global skill，其他设置保持一致。所有组的原始问答一起按官方十任务macro汇总。该实验只干预Global首选，不把依据原问题预分配的Video卡当作符合Video信息边界的线上选择。Video手动路由若增加，需要在实际instruction产生后，依据该VideoAgent可见信息单独做。

手动路由是机制诊断，不直接作为自然整库接受成绩。分别报告覆盖率、选中子集的配对收益与损失、弃选题是否复现空库答案，以及全80题宏观成绩。高弃选率不是成功指标；错误选中仍可能造成退步。若这种保守分配有效，再研究由Train反馈收窄when_to_use与增加strategy排除条件的进化方式；正式候选仍以自然整库的官方总分比较，不添加成本或步骤目标，也不承诺严格不退步。

资源按用户最新指示调整为当前实验合计最多64 H100。已有48卡测试正常运行；新工作只有在对应旧分组真实释放后才接续申请，不能将“已答完”误认为GPU已释放。

## 偏保守的进化应保证什么

保守性分为两件事。第一件是运行时隔离：不选卡时不注入策略、选卡理由或额外指令，Actor使用原来的输入与动作接口。可用同题消息、实际输入/输出token和答案核对这一点；它保证没有引入文本干预，不是任意硬件或执行条件下的输出不变证明。第二件是选卡有益性：即使弃选题完全复现空库，选错的非空卡仍可能使整库退步。因此不能用高弃选率替代最终准确率。

在上述诊断完成之前，不预设增加“更谨慎”措辞就有效。后续候选生成可优先采用以下受限改动，但它们目前是待检验的方法设计：

1. 从空库开始，一次只改一个角色的一张卡。根据Train中完整问答的改善和退步实例，提出可被输入识别的适用关系；不给生成器任务代号、题号或预设题型标签。
2. 将真正决定是否适用的条件写进`when_to_use`；执行时仍需遵守的前提与排除条件也写进`strategy`，因为Actor看不到`when_to_use`。正文给具体动作与证据要求，不泛泛要求“更加仔细”。
3. Train上的手动选择、固定注入和同卡执行差异用于定位问题；频次、编号稳定性和误选实例是诊断信息。不能因某种描述更少触发，就认定它更安全或得分更高。
4. 候选依然以完整库自然选择跑Cal/Gate，正式接受仅看官方总分。未达到原接受条件则保留已有库；不把手动分配成绩、选中率、成本或步骤数加入接受目标。

需要同时报告整库收益、选中题的收益与损失、弃选题的差异，以及被保守规则取消的选择是否实际有益。只有当“取消有害干预”带来的收益超过“错过有益干预”的损失，保守选择才有价值。有限开发样本上的接受或回退仍不能保证未来题目逐题不退步。
