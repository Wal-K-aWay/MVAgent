# 手工设计 Skill 的机制检验

目标是检验策略文本和自动选卡是否能提高冻结 MVAgent 的准确率，不预设正结果，也不把所有失败归因于生成器。卡片由研究助手根据 Train 公开轨迹设计，不称为人类专家标注。Global 和 Video 的输入边界分别保持不变。

## 预先固定的比较

1. 用现有 Train80 中每类前两题组成 Train20。包括空库、逐张固定注入，以及完整角色库自动选卡。固定注入使用运行时已有 static 模式，注入正文与动态选中后的正文完全一致，仅用于诊断。
2. Global 三种策略：直接共同观察比较、保持同一判定标准、基于事件确定时间。Video 两种策略：保留逐项证据、获取事件边界。每种均有简短版与步骤版；两者内容详细程度也不同，因此不能将差异单独归因于长度。
3. Selector 固定正文，比较宽泛描述、关系描述、带排除条件描述，并交换编号顺序。使用真实 Selector Prompt 与模型。选中率、弃选率、编号敏感性分别报告；高选中率不等于选得正确。
4. 按 Train 结果选择至多两套自然选卡库，在现有 Cal40 上比较。冻结其中一套后，优先使用新准备的、与当前开发划分来源组隔离的 Gate200 做确认。Gate 不足时明确报告实际可用样本与限制，不以此阻塞首轮 Train 测量。Cal 与 Gate 的题目细节不提供给卡片作者。

## 判断口径

主指标为 CrossVid 十任务 macro，CCQA 按官方知识点权重聚合。报告有效样本数、每题配对收益/损失、分任务成绩及固定种子的分层 bootstrap 区间；探索性多臂筛选的 Train 最优值不能当作独立确认效果。最终自然选择的整库结果才用于机制有效性的主张，固定注入结果用于定位策略正文与选择之间的差距。

新测量最多使用两组 H100:8；Actor 冻结为 Qwen3.5-35B-A3B，沿用已验收配置和官方 Judge。每组七个 Actor 副本与一个 Judge，原有 48 H100 测试保持独立。每个运行保存源码、配置、库哈希、原始轨迹与评分；结果留在 Modal runs volume。

复用历史空库轨迹必须核对模型、Actor 源码、输入与协议，并保存来源和原始哈希；不将不兼容协议拼接为同一对照。若同一答案在独立 Judge 副本出现差异，分析采用预先固定的来源优先顺序统一相同评分请求，保留并报告原始差异，不择优取分。

## 解释结果

- 固定注入提升而自然选择不提升：提示选卡遗漏、误选或库内竞争，继续定位选择问题。
- 两者都提升且独立确认有效：支持存在有用策略及当前选择接口能利用它，但不能证明未来进化算法有效。
- 固定注入也不提升：当前卡片、任务适配或注入方式仍无充分支持；不能写成“仅生成算法不好”。
- 只在开发集提升或少量题改善：作为探索性证据保留，需要独立确认。
