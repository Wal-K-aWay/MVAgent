# 直接联合观看优先：补充诊断卡

对应 [`manual_watch_first_bank.json`](../src/skill_evolution/configs/manual_watch_first_bank.json)。这是助手手工设计的额外诊断卡；此前三张 Global、两张 Video 的实验库保持冻结，补充卡独立评估。依据是用户历史上强制 `watch_videos` 在特定失败子集中约 47% 恢复的观察，以及此前 Train 公开轨迹中丢失跨视频关系、局部指令改写原问题的现象；历史比例尚未在当前协议复现。本轮已知 Train 汇总分只能说明现有柔性卡没有显示改善，不能预设本卡会有效。没有依据 Cal/Gate 逐题信息调整。

JSON 是 `schema_version: 3` 的单卡库；卡片 ID 为 `1`，角色为 `global`，阶段为 `initial` 和 `evidence`。

## `when_to_use` 完整中文镜像

题目需要结合两个到四个输入视频的证据。在生成各视频的独立摘要之前，带着原始问题联合观看这些视频，有助于保留跨视频关系。排除输入视频超过四个，或答案相关的问题与选项无法放入一条 1600 字符的视觉分析指令的请求。

## `strategy` 完整中文镜像

输入视频为两个到四个且 `watch_videos` 可用时应用本流程。第一个取证动作使用 `watch_videos`，放在 `analyze_videos` 之前；每个输入视频只选择一次，每个视频使用一个合法的源时间片段。题目给定的区间确实界定所需证据时使用该区间；否则覆盖该视频完整的 `[0, duration_sec]` 区间。每个已给出的区间只归属于它所指明的视频，不把参考视频的区间复制给另一个视频。绝不提供 `fps`。

观察器只能收到你的指令：点明每个所选视频 ID，并保留原始问题、所有答案相关选项以及对象标签、量词、同步关系和时间限定。在 1600 字符指令上限内，仅删除冗余的任务套话。请求能够解决问题、区分各候选解释的可见证据以及不确定性，不要求观察器选择最终答案。如果无法容纳关键语义，则不应用本流程。

返回证据足以解决问题时立即回答。如果某个具体缺失细节可能改变答案，进行聚焦的联合观察，或提出仅凭单个视频即可回答的局部分析请求，然后重新判断。宽范围采样可能遗漏短暂细节；失败的观看不构成证据。回答之前最多使用四个取证动作，并遵守既有结束机制。保留来源身份与题目要求的答案格式，不编造未看到的观察。

## 相对于 `joint_compare` 的可观察改变

- 原 `joint_compare` 允许先调用 `analyze_videos` 定位，也可能只在后续认为有必要时调用 `watch_videos`；本卡适用时把首个取证动作明确固定为联合观看所有输入视频。
- 原卡把问题转换为某个待比较的视觉特征；本卡把原问题及全部答案相关选项、量词、身份和时间条件带入观察器，检验先保留完整任务语义是否能减少分解时的信息损失。
- 未给出定位锚点时，本卡从完整视频范围获取联合证据。它可能使长视频采样更稀疏，这是需要实测的取舍，不能把强制动作遵循率当正确率。
- 观察器仍只返回证据，Global 仍负责综合与终答；没有添加工具、改变角色信息边界或允许观察器直接选最终答案。

记录时可直接检查第一动作是否 `watch_videos`、是否覆盖全部适用视频、观察指令是否保留关键语义，以及完整问答评分。若后来仅更换这张卡，仍须保存独立库哈希并运行完整 rollout；不能热改现有实验。静态强选只能诊断策略是否有用，自然选择仍须单独测量。
