# MVAgent：第二轮机制探索与免训练进化

本轮从2026-10-21 16:59 UTC开始，目标在约8–9小时内交付更多完整实验、可证伪的机制结论和经过实测的进化方案。总GPU上限64张H100，包含原先仍在运行的全量测试。本文记录预先约定的判断方式；计划数量不代表已完成实验。

## 为什么继续探索

[上一轮结果](manual-skill-results.md)显示，9B简短Global库用Codex盲选比原Selector高6.44个百分点，主要收益来自原先弃选的题；同一保守分配对两种正文的效果方向相反。Video简短库在Cal的正差也没有在Gate延续。不能据此默认正文、选择器或生成器中的某一个是唯一问题。

本轮先问更基础的问题：**部署时可见的信息是否足以判断某个具体程序值得执行，而这个程序能否改变正确的证据获取环节？** 语义相关、选中、注入、遵循和最终有益是不同环节，必须分别观察。

## 竞争解释及最小实验

| 假说 | 保持不变 | 实际干预与观察 | 不支持该解释的结果 |
|---|---|---|---|
| 存在有用正文，但初始路由漏掉它 | 9B、题目、动作预算、工具、评分 | 补齐三张简短Global卡的Train80固定注入对照，和空库、自然路由比较 | 20题正差在新增60题不延续，或所有固定方法都无净收益 |
| 适用描述/编号改变有益的选择 | strategy和Actor不变 | broad、relation、contrastive及重编号；先离线看选择，再完整自然E2E | 选择改变而官方总分不改善，或变化只反映编号偏好 |
| 联合观看解决信息拆分损失 | 同一MVAgent | watch-first固定注入扩到80题，记录实际视觉请求与退化 | 严格执行仍不改善；不能继续只责怪未选中 |
| Video策略没有传进视觉读取 | instruction和现有工具 | 检查strategy→observe.what→观察证据→报告，修订一项明确传递规则 | 请求确已传递，但新观察依然错误或最终答案不受益 |
| 好坏取决于观察后才可知的信息 | 初始Selector接口冻结 | 将可见入口与观察后条件动作分开，条件分支写在strategy | 条件被正确识别并执行后仍无收益 |
| 效用取决于模型与其他角色 | 同一卡片/相同问题 | 有实测信号后做角色组合、较强本地Selector/消费模型对照 | 改善只来自更强模型本身，或换搭档即反转 |

固定注入、人工分配和离线反事实拼接仅用于Train诊断，不作为自然库接受成绩。离线计算的逐题最优选择是事后机会估计，不是可实现的Selector。Video旧instruction上的离线选择不能替代新的完整问答，因为后续指令和报告会相互影响。

## 首波已经冻结的测量

复用已验证的源码`2d3085f`、Qwen3.5-9B和原80/40/176清单，模型推理seed=0，其他预算不变。154个Actor、模型和推理配置文件与旧9B源码逐字节一致；旧空库Train80作为参考，不重复运行。扩到80题的固定策略保留原20题与新增60题的分开结果；重复题不增加独立样本量。

| 并行节点 | 首个完整测量 | 不同题数 |
|---|---|---:|
| 0 | Global简短时间锚点卡固定注入 | 80 |
| 1 | Global简短库，broad入口自然选择 | 80 |
| 2 | Video简短库，broad入口自然选择 | 80 |
| 3 | watch-first卡固定注入 | 80 |

四节点各7个Actor副本和1个固定Judge，新增32张H100；原测试仍占32张。独立控制器先核对真实释放状态及配额，再申请资源。后续互不依赖的测量并行排入已加载节点，避免反复加载模型；不向旧全量测试的模型服务插入请求。所有实际运行独立冻结源码、配置、库、清单与原始输出。

## 文献提供的约束与适配

| 一手工作 | 借鉴内容 | 在MVAgent中的具体限制 |
|---|---|---|
| [SkillOpt](https://arxiv.org/html/2605.23904v1) | 利用多轮执行反馈编辑程序性文字，比较更新前后经验 | 不照搬其题号、选择集反馈或更宽编辑权限；优化器只读Train角色公开视图 |
| [Skill Consumption](https://arxiv.org/html/2605.23899v1) | 区分提取经验的能力和使用技能的能力；文字看似合理不等于有效 | 强优化模型不必然解决9B无法执行的问题；分别测固定正文效用与提案质量 |
| [Skill Usage](https://arxiv.org/html/2604.04323v1) | 将选择、检索、适配损失分开，研究面向当前问题的细化 | 不添加在线refiner；用strategy指导Actor将通用方法实例化为当前证据判据 |
| [GEPA](https://arxiv.org/abs/2507.19457) | 用自然语言反思真实轨迹，保留互补尝试 | 先测是否确有互补收益；没有证据就不增加Pareto池或复杂搜索层 |
| [ExpeL](https://arxiv.org/abs/2305.14794)、[ReasoningBank](https://arxiv.org/abs/2509.25140) | 从成功、失败及同题不同经验中提取规则 | 对照来自明确的skill干预；不把幸运答对当成功方法，也不把任务记忆部署成答案库 |
| [ACE](https://arxiv.org/abs/2510.04618) | 增量编辑，避免全量重写抹掉有用细节 | 单卡与1200词限制不适合照搬长playbook；长度不是优化目标 |
| [MASPO](https://arxiv.org/abs/2605.06623) | 局部行为与最终结果、搭档策略之间可能不一致 | 保持角色边界；Video整题得分不变成局部正确率标签，搭档变化后完整重跑 |
| [Video-RSI](https://arxiv.org/html/2609.37950v1) | 主动获取新证据以检验竞争失败解释 | 只通过Train完整rollout使用现有观察工具；不让优化器越权看视频或改harness |
| [LensWalk](https://arxiv.org/abs/2603.24558)、[AgentCVR](https://arxiv.org/abs/2605.29643) | 观察位置、采样方式和跨视频证据关联 | 借鉴已有action参数的控制方法，不新增工具、记忆模块或权重训练 |

这些是受限适配，而非复现论文效果。特别要检查：skill不会自动进入Observer，也不会自动进入Video强制总结；想改变感知问题或报告证据，必须通过已有instruction、observe.what和返回证据传递。只统计选中率会漏掉这个问题。

## 第二轮证据要求重新区分的目标

补齐同题固定正文后，三张常量卡在Train80均高于自然三卡路由；但这还没有证明初始题面能预测哪张正文更有用。令`X`为首次Selector可见输入，`R_s`为固定正文`s`下的整题得分，应区分三个值：最佳常量`max_s E[R_s]`、可实现的初始路由`E_X[max_s E[R_s|X]]`、事后最优`E[max_s R_s]`。中间值未知，不能把事后最优与常量的差全当作可学习路由空间。实际统计仍按官方十任务macro及CCQA权重，不能用该简写替换评分。

[Dynamic LLM Routers are Often Misguided](https://arxiv.org/html/2610.02762v1)提供了语义名单选择可能低于随机组合的实证，但其成本目标不移植到这里。[Learning to Defer](https://proceedings.mlr.press/v119/mozannar20b.html)比较两个都会出错的系统；这更接近我们的skill与none：none仍完整执行Actor，不是从评估分母里拒答。因此高弃选率不是安全目标，必须估计相对空库收益。[RouteLLM](https://arxiv.org/html/2406.18665v4)借助成对偏好学习相对胜率，也不能被解释为只凭技能主题即可知道实际效用；本项目只借这个优化对象，不训练新的路由模型。

[COBRA-Skills](https://arxiv.org/html/2609.11682v1)的context是候选skill的表示，reward是优化集均值，最后选一张高均值卡；它解决优化期评估预算分配，并未解决部署时的query→skill选择。当前候选少且完整反事实表已有，不先添加surrogate或bandit模块。先比较单个高均值正文经自然选择部署与多卡库，检验个性化路由的额外价值。

[SPARO](https://arxiv.org/html/2609.32492v1)用实际干预区分激活和正文问题，可借鉴固定正文只改入口、固定入口只改正文的诊断。[AgentGrad](https://arxiv.org/html/2609.08572v1)先干预一个Agent并测下游是否修复，但其GT-derived hint违反本项目优化信息边界，不能照搬。[MIPRO](https://arxiv.org/html/2406.11695v2)提示模块组合有交互；本轮只在已有单角色结果之后测试一个G×V组合，不把可能交互扩成无限矩阵。

据此有三条互斥的下一步假说，不预先认定都需要实现：

1. **可见相对收益。** 保持正文不变，以Train同题收益与损失约束一次入口修订；先查表诊断，再真实完整自然运行。若只改变选择却未胜过常量或未跨来源保留优势，停止同义入口搜索。
2. **观察后条件程序。** 一次选卡不禁止已选正文根据后来报告决定动作。对末句控制只增加一个有证据支持的条件操作，条件写在strategy而非要求Selector提前知道历史；若对应action参数没变化，不能把分数变化归于程序被执行。
3. **单个消息边界保真。** 根据该角色可见Train，定位题目→instruction、instruction→what或观察→正常finish的一处丢失，只改该角色一张卡。若判据已完整传递仍错，转向感知或综合能力解释，不继续堆报告格式。

上面是适配与反证设计，不是这些论文已在MVAgent复现。卡片的真实价值属于Actor、正文、搭档库和诱发的观察链条共同组成的系统；reason复述了策略，也不足以证明该策略造成得分提升。最终接受仍只看自然完整库的官方总分。

本地两次提案完成后，可用[GLM优化器配置](../configs/skill_evolution/glm_optimizer.yaml)对相同Train-only messages/schema做强优化模型对照。该配置使用现有BigModel客户端和环境变量凭据，不改变Actor；GLM-5.3按[官方协议](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)开启thinking/high、16384输出token。与9B相比，模型、思考预算和JSON约束编码均不同：BigModel客户端会增加schema系统消息，不能声称只有权重变化。准备配置不等于已调用或已测得收益。

## 当前证据要求优先回答的问题（23:06 UTC）

核心问题是：**在当前Actor和取证链条下，能否找到跨来源仍有净效用的文本干预，以及选择时可见的信息是否足以识别这种效用？** 这比增加库大小或提高激活率更基础。已测完整程序在三种Actor上均未显示优于终答一句的稳定增量；两种更强Selector虽然改善了原路由，查表结果仍低于最佳常量及频率匹配随机期望；一个按Gate规则接受的库也没有在365题上超过该控制策略。它们不能证明所有skill无效，尤其不能替代同协议空库比较，但足以阻止把小面板正差直接当作可泛化能力。

还应区分卡片的覆盖范围和一次编辑的范围。[真实Selector](../src/mvagent/skills/prompts.py)要求入口方法能覆盖问题的主要操作；仅有收集相关观察的技巧，不自动构成排序、匹配或判断的方法。卡片应是一项自包含工作流程，而一次进化可以只修改流程中的一个条件操作。这并不要求新增卡片字段或修改Selector。

静态审查也不能把“重复基础Prompt”直接等同于无用。terminal主要重述基础证据与格式要求；temporal的工具边界部分已有基础说明，但先获取参考事实再传入后续instruction、匹配后核实两端而不照抄时长，是额外程序。首个接受库的中立描述优先、具体异常标志与针对性再取证也是额外限制。已有基础循环本来就允许多步，不能采用卡片中“默认单遍流程”的措辞作为系统事实。文字是否新增、操作是否发生、操作是否带来净收益，是三个不同判断。

下一版研究先沿用已实现的角色轮换、合法Train投影和自然整库Cal/Gate，不把这些已有能力重新包装成创新。待验证的最小变化是在完整卡片内固定入口与伙伴库，只改变一个由Train公开证据支持的行为组件；新增或修订入口时，明确哪些条件可在选择前判断、哪些只能由Actor在观察后判断。Stage2–3联合删除是该方向的诊断，仍有长度混杂；目前尚未证明这种受限搜索优于现有rolewise。

必要的强选诊断只使用Train、仍跑完整问答，并与自然结果分开。强选绕过适用条件，因此整体负差不能否定适用子集的价值，整体正差也不自动构成可部署收益。Video首卡的239次自然弃选、480次强制规划实际注入以及未见整体正差，正好说明不能只修入口而默认正文有效。其重复零长度区间在错误反馈可见时仍发生，还表明文本规则与反馈不保证Actor执行。

要形成方法论文，后续必须在相同优化模型、信息权限和完整rollout预算下，比较无反馈一次生成、一次Train蒸馏、现有迭代基线与新方法；DeepSeek一次生成和GLM反馈编辑不能直接隔离“反馈”的作用。重复使用80/40/176及365仍是开发过程。扩大独立来源覆盖、冻结后确认、完整记录所有候选和退步，比继续在同一小Cal上挑最高分更能增加结论可信度；接受本身仍遵循官方总分，不临时加成本目标或改变本轮阈值。

## 原定时间安排与转向规则

- 前约1.5小时：先完成首波主指标，继续补反事实表与入口对照；文献和轨迹分析并行。
- 约1.5–3.5小时：依据Train真实差异提出少量可执行条件卡，测证据传递、角色组合或消费模型差异；优先解决最大的不确定因素。
- 约3.5–6小时：先让本地优化模型完成一次可审计的提案—完整评估闭环。只有实验已给出可用反馈，才考虑GLM优化模型；凭据只在环境变量或Modal Secret中使用。
- 余下时间：冻结候选做Cal/Gate确认、必要的模型迁移与总结。不给最终Test反馈用于优化；时间不足时缩减非必要矩阵，保留负结果和未验证事项。

时间划分是预算，不是等待门槛。一个小的端到端测量无需等待整个矩阵完成。连续两次修订没有形成预期行为或留出收益时，停止同类措辞微调，回看究竟缺少可用正文、可见触发条件、正确视觉证据，还是可执行预算。每次转向应提出一个能区别这些解释的干预，而不是换一个算法名称继续相同搜索。

候选始终完整自然选卡评估，接受只看官方总分；不加入选中率、步数、token或成本门槛。Cal/Gate重复使用仍是开发验证，所有尝试记账；已有Gate负结果不能靠重命名新分区消除。代码沿用configs/infra/algorithms分层，评测留在eval，冻结的Actor架构保持不变。
