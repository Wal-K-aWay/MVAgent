# 专门化程序性 skill 卡：证据边界与首测预测

核验时间：2026-11-04 UTC。以下只引原论文与作者官方仓库；未复现上游实验，不使用本项目Gate/Test案例推导卡片。当前用户明确要求先测试Codex手写样例，取代历史研究中暂不测手写对照的取舍。

**结论：值得先做 Codex 手写样例的完整 rollout；现有研究支持“冻结模型可以受益于可复用程序性指导、相关经验选择和有结构的规则”，尚不足以证明“多个自然语言专门卡 + 每题选一张”优于一个文档，更没有证明指定标题、六类划分或某个字数最优。** 对 MVAgent 的多视频视觉取证，关键是正文能改变有效观察和证据组合，不能以排版完整或选中率代替准确率证据。

## 六项最相关的原始证据

### 1. ExpeL：自然语言经验与相关经验检索有增益，也有明确负结果

冻结 GPT-3.5 执行，GPT-4 提取经验；HotpotQA、ALFWorld、WebShop 都是**文本观察**。ALFWorld 的“只检索经验”R0 为54.5%，加 insights 为59.0%；任务相似检索59.0%，随机检索42.5%。HotpotQA 手写 insights 32.0%，ReAct 28.0%，自动 insights 39.0%；额外加入反思文本反而降至29.0%。这是相关内容与抽象指导有用的证据，也是“内容更多未必更好”的负证据。检索对象主要是成功轨迹，insights 整体放入上下文，不能当作多卡 Selector 的消融；手写与生成的差别同时包含内容质量和生成模型能力。

来源：[论文 v3 §5.5–5.6、表2–3、§6](https://arxiv.org/html/2308.10144v3)、[官方代码](https://github.com/LeapLabTHU/ExpeL)。

### 2. AutoManual：对结构与具体内容最接近的消融，但不是纯排版实验

GPT-4-turbo 在 ALFWorld 134道 unseen 任务上：完整系统97.4%；删规则 Type 为91.5%，删 Example 为92.7%，删 Validation Logs 为97.0%；不做最终 manual formulation 为96.5%。但删 Type **同时删 Builder 管理类型的指令**，删 Example **同时删内容细节**；不能归因于字段名或视觉格式。系统还有程序库、反思库和在线规则更新。作者观察跨任务共享规则有利，而仅模仿成功路径的库容易受路径依赖影响；这支持“方法可复用且有条件”，不支持机械地按题型切得越细越好。任务类型可见、代码交互等条件与本项目不同。

来源：[论文 v3 §3.3–3.4、§4.2、附录F.1/表7](https://arxiv.org/html/2405.16247v3)、[官方代码](https://github.com/minghchen/automanual)。

### 3. Voyager：可检索模块库确实有消融，模块是可执行代码

冻结 GPT-4，在 Minecraft 中按描述检索 top5 已成功的代码 skill，再合成新程序。每项3次试验；未见任务 Diamond Pickaxe，完整库3/3成功、19±3次 prompting；去库2/3、36次；去库在开放探索后期停滞。309条检索样本 top5 accuracy 96.5%。它支持“存储并检索可组合方法”，没有分离“模块化”和“检索”的各自作用，也没有比较同内容单文档。原实验 GPT-4 只收文本状态，**不是视觉感知证据**；代码直接扩展执行能力，与只注入自然语言 strategy 的迁移距离很大。

来源：[论文 v2 §2.2、表2、§3.4、附录B.4.4、§3.5](https://arxiv.org/html/2305.16291v2)、[官方代码](https://github.com/MineDojo/Voyager)。

### 4. SkillOpt：冻结 Actor + 程序性外部文本可有效；它恰好优化单文档

六个 benchmark、七个目标模型、三种 harness；目标模型和 harness 固定，优化一份 `best_skill.md`。GPT-5.5 direct-chat 的 DocVQA 为78.8→91.2，ALFWorld83.6→95.5。成品约300–2000 tokens，优化器的有界编辑、拒绝缓冲等有消融。它是文本层可改变取证/行动流程的支持；**不支持库或问题路由必需**。成品长度是观察量，没有等内容长度扫描；优化控制的消融也不能证明“Evidence/Stop”写法。DocVQA涉及文档视觉，但没有多视频取证结果。

来源：[论文 v1 §4、表1/3/6](https://arxiv.org/html/2605.23904v1)、[官方代码](https://github.com/microsoft/SkillOpt)。

### 5. GEPA：冻结模型的文字指导可以优化；其“模块”不是运行时选卡

固定模型，反思 execution traces 后优化一个或多个系统模块的 prompt，覆盖多跳QA、指令遵循、隐私委派、验证和数学。Qwen3-8B 的表3中，Pareto父代搜索的 aggregate 为61.28，贪心54.89、beam53.95，说明搜索策略影响最终结果；不是卡片排版效应。合并候选对小模型还可能退化。不能把方法整体收益转写成“专门卡一定优于泛化说明”，也不能把多个系统模块误当成每题检索选卡。它未提供视觉/多视频的直接迁移证据。

来源：[论文 v2 §3、§4观察2–5/表3](https://arxiv.org/html/2507.19457v2)、[官方代码](https://github.com/gepa-ai/gepa)。

### 6. Video-RSI：视觉取证流程值得改，但它改的是 harness 代码

冻结 DeepSeek-V4-Pro solver/editor 和 Qwen3.6-Plus视觉服务；216道 LVBench Train、72道 video-disjoint选择集、20次修订。表2中 MLVU 的 trace-only64.7%/60.3帧，允许主动调查72.9%/61.1帧；支持补充证据能改善修订依据。它可以改 prompt、工具、观察表示、memory和执行控制，**不是只改 skill 文本**；推理帧数还不包含离线调查成本。故可迁移的只是“保持时间/实体/证据关联、针对歧义取证”的假设，不能把整体提升记在卡片写法上。初次被接受版本还曾使外部 MLVU 成绩下降。

来源：[论文 v1 §3.1、§4.1、表2、§4.4](https://arxiv.org/html/2609.37950v1)、[官方代码](https://github.com/bingjunluo/Video-RSI)。

## 目前能与不能声称

| 写法或机制 | 本次找到的证据 | 对当前试验的含义 |
|---|---|---|
| 外部程序性文本 | 有冻结模型、无权重更新的实证；部分有视觉文档任务 | 可以先测手写正文，不能先保证收益 |
| 模块库 + 相关路由 | 代码库/轨迹检索有消融；未找到同内容自然语言多卡与单文档的直接配对 | 适配本项目后仍是待检验假设 |
| 清楚作用范围、具体步骤/例外 | AutoManual结构与细节消融提供间接支持 | 不把删内容的收益称为字段格式因果 |
| 明确证据要求与停止条件 | 在方法/成品中存在；未找到单独、匹配预算的拆除消融 | 作为可执行设计测试，不能称已证实的最优模板 |
| 固定标题、六类、卡长/数量 | 未找到直接实证 | 不强制这些外形；1200词等现有契约只是上限 |

“未找到”仅限上述六项原始来源及本次检索范围，不宣称整个领域不存在。没有一项研究同时满足本项目的双角色信息边界、自然选择最多一张/可none、多视频工具、固定预算和官方整库总分。

## 对手写首测的五条可证伪预测

以下是本项目的**推断与预注册假设**，不是论文结论。首个完整测量无需等待后续诊断；先冻结手写库，用现有自然选卡跑约定Train，与已经完成且身份匹配的空库参照比较，不重跑已成功的无skill/无反馈一次生成条件。当前[P/S固定计划](../configs/skill_evolution/manual_procedure_20261104.json)各测400道不同Train题，正文操作句相同；两版布局差异单列为有限诊断，不查询已使用的Gate。后续只针对首测出现的行为证据选择一项最小对照。

1. **具体取证程序应改变有效证据。** 在适用样本中，选中后应更常获得问题需要的跨视频对齐/身份/时序证据，且配对修复超过退化；只提高选中率或报告完整度而不提高官方分数，不能支持有效性。
2. **入口范围有价值时，应减少有害激活。** 固定strategy，仅收窄可见触发与排除条件；预测退化减少，同时保留多数修复。若只把所有题都推向none，或修复损失同样大，预测失败。
3. **程序内容应胜过同长度空泛提醒。** 固定入口和角色，把“仔细检查/合理采样”换成具体行动与证据关联；预测行为与得分改善。若只有字数增长、额外调用或更强模型解释增益，不能归因于程序性写法。
4. **Evidence/Stop应有净收益而非迫使过早结束。** 固定其他正文，拿掉这两类要求时，预测无效重复或缺证据终答增加；若加回后漏观察、过早answer或准确率下降，就否定该版本，不能以省步数补偿总分退化。
5. **细分卡应体现路由收益，而非越专门越好。** 先找正文相近/入口重叠的卡，仅合并这一对并保持信息尽量相同；预测原细分库只有在选择更准确、净分更高时才占优。合并持平或更好，即反驳该处分卡必要性；无需先预设六类或全面扫卡数。

保持Actor、工具、帧/步骤预算、推理seed和评分不变；行为指标只解释机制，接受/主结论仍看完整库官方分数、有效样本、修复/退化与配对不确定性。Global和Video可观察信息不同，正文须自包含；不能靠另一字段或另一角色补上不可见前提。

未做上游复现、最优长度/卡数搜索或Gate/Test分析；外部结果到MVAgent的迁移仍须由本次完整rollout验证。
