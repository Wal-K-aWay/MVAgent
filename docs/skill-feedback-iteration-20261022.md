# Skill 反馈组织与分角色迭代实验

本轮承接[输入审查](skill-optimizer-input-audit-20261022.md)和[上一轮交接](skill-research-handoff-20261022.md)。用户要求把新分析保存到GitHub，并继续实际实验。本文随完整测量更新；计划、格式检查和模型成功产出均不算准确率实验完成。

## 研究依据

上一轮形式上交替Global→Video，每次只改单角色；最终只接受首Global。实际八个提案累计仅接触29道Train题，两个Video请求完全相同，缺少跨轮失败经验。一次Video配对反馈7对中6对仅选卡记录不同。正式截断11/95，并非when-only的30/32；GLM没有耗尽输出预算。Memory投影缺陷已定位，但正式Train没有触发，不能用它解释旧分数。

Global和Video需要不同的提案依据，验收仍共享最终官方总分。最终GT只由评测器使用；两角色优化器都不直接读取GT。Video没有局部报告真值，固定Global库后比较完整系统的分数差可以测其系统贡献，但不能把整题得分复制为每份报告的对错。固定Global文本不固定其后续动作，新的Video报告应自然影响全局决策。

## 本轮顺序与预算

1. 修复Video投影的持久Memory语义，保留本次错误和终止反馈；补目标Actor消费预算及真实Selector静态契约，保持Actor与Selector本身不变。
2. 首先做Global反馈表示对照。固定父库、Train案例、先前试验、模型、提案数和评估清单，只改变输入的组织方式。第一张有效事件格式候选立即进入端到端评估，不等待全部候选。
3. 固定同一Global父库做Video对照，使用它实际产生的instruction分布。Video阶段不会基于Global本轮中途成绩随意更换伙伴。
4. 冻结新库以后进行更大覆盖或新来源确认。准备与旧源组隔离的十任务面板可以并行开展；不能把重复开发集重新命名为独立Test。

每角色3条件×2独立提案，共6候选；两个角色完整执行上限12候选。第一波只运行Global六候选。阶段预算：输入与远端验证约30分钟，Global约2小时，Video约2小时，后续确认约2小时；基础设施故障优先缩减新分支，不追着有利分数延长窗口。GPU总占用不超过64张H100；生成和CPU校验不占GPU，节点等待无任务时释放。

## 第一波预声明对照

共同父库为已接受的Global库`4765323a0d13b5df3402a00b29fe242f0543dd6f82dc30377595e83668f2ad55`，Video库为空。采用9B固定推理profile、seed=0、temperature=0、thinking关闭、2048输出token、Global/Video各5步与原帧预算；Judge沿用原身份。

| 条件 | 输入 | 提案数 |
|---|---|---:|
| 旧表示 | 完整合法投影按原规则首尾截断；保留共同新增契约与Train汇总 | 2 |
| 事件表示 | 相同案例；公共字段去重、父候选独立事件序列、完整事件省略标记 | 2 |
| 无反馈编辑 | 相同父库和消费契约，不提供Train轨迹、分数或先前候选 | 2 |

无反馈编辑是从当前父库出发的编辑对照，不是从空库一次生成，更不是从空库正式算法的结果。各提案不互相读取输出；每个有效新库都自然运行完整Train80/Cal40/Gate176，Gate在此作为预声明报告对照，不因Cal中间排名选择性隐藏。Cal/Gate逐题内容永不进入optimizer；若讨论正式接受，仍必须同时满足原Cal与Gate严格总分增益规则。

Global反馈固定为原第2轮第二候选所用的父4765与试验27cc2c13的同题Train材料；它包含本轮原本已被optimizer读取的案例，不引入Gate/Test反馈。Video阶段拟用原第3轮第二候选的合法配对材料。问题与任务ID仅用于审计定位，不进入Prompt。

两个反馈条件使用相同Train全批官方总分、改善/退化/持平数量。两组的差别只在案例表示；它们与无反馈编辑比较时，差别包括整个Train反馈包，不能单独归因于格式。GLM配置复用既有glm-5.3、high、temperature=1、top_p=.95、16384输出token；没有证据支持先调温度或扩输出额度。

noop、重复库和返回空库均保留为提案结果，不免费补提案，不重新推理已知同协议空库。所有格式错误和失败都报告。候选文字不人工修改后冒充模型生成。

## 输入与运行检查

- 原始请求和响应先落盘，随后schema、卡片词数、render和角色编辑范围检查。
- 新表示只处理角色公开投影；不新增标准答案、Judge评分点、兄弟Video信息或未观察的视频事实。
- 共同问题/instruction、答案/报告、选择结果及反馈保留；省略发生在完整事件边界，不能切半个JSON字符串。必要字段本身超预算时报错，先处理该真实输入，不静默截断。
- 对照固定相同完整案例身份；测试引号、中文、嵌套JSON、无变化轨迹和两请求Memory。首次真实API前保存并人工查看实际输入样例和统计。
- Actor/Selector/runtime源码和配置与旧协议核对；新GPU服务验证实际manifest、prefix关闭、单卡副本及seed，不重复已通过的无关数值实验。
- 已观察到runs volume接近500000目录项上限。批量评估前仅无损归档已完成的重复native src/eval快照，逐文件校验并保留恢复索引；raw、评分、库和配置不删除。容量检查通过即开始首个端到端单元，不以无限审计代替运行。

## 后续分支

如果事件表示没有改善提案或总分，不将失败自动归因于“skill没用”：检查是否只是信息去重、关键行为未变或生成方差；下一对照改变案例相关性或跨轮Train记忆，并分别控制变量。

如果无反馈编辑表现相当或更好，保留该简单对照，研究反馈是否诱导了过度复核或局部过拟合；不删除负结果。两次生成不足以比较方法的完整分布。

如果Global稳定、Video仍无益，先检查实际激活与局部动作变化，再决定是否需要更好的指令内任务分解或反馈。不得伪造Video局部GT，不为两库都非空强行接受。

新来源确认与原一次生成强库的比较保留为后续重点。只有独立确认后才讨论稳定泛化；CVBench/MVU不进入优化，既有历史接触仍须披露。
