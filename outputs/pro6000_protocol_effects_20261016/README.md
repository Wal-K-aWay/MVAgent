# PRO6000、回答协议与模型差异：同300题分析

2026-10-16，仅使用已保存输出做Modal CPU分析，无新推理、无Judge、未修改正式src/eval/configs。主分析app `ap-ZCyaErLwPz3jpPXJTJWUd2` rc0，原始/派生数据仅runs volume `devbox/pro6000_protocol_effects_20261016`；脚本`scripts/analyze_protocol_effects.py`。

## 比较对象与边界

这里的“直接协议”专指10月15日900配对中的冻结源码：主动回答直接提交、History在动作说明后、耗尽步数用answer-only决策。10月16日刚恢复的History前置+独立兜底只有三题功能/一致性冒烟，没有准确率面板，不能与前一轮协议混为一谈。

沿用三模型相同300题，每benchmark100，从共同完成1375题的开发池按task抽样，不重新选题。三模型的PRO Agent、PRO E2E、迁入后的独立回答器、前一轮直接协议、当前E2E原位置和MVU指令移后，共六个视图全部用同一冻结评分器重算。旧E2E FSA列表统一序列化为start,end；CV Yes/No和参考尾空格遵循已有评分契约。不改变原结果和原得分文件。

所有900条独立/直接分数、稳健分、格式和空答案统计与已发布面板逐题一致；历史独立答案与原PRO对齐数据逐条吻合。保存输入文件SHA、逐题六视图、评分器身份。CV/MVU按task人口加权，Cross为九闭式task macro（含FSA连续IoU），不含CCQA。

区间为同题、task内配对bootstrap，2000抽样、seed0，未做多重比较校正，也未按共享视频聚类。此次固定按题号排序后抽样，有限Monte Carlo抽样使区间端点与之前报告略有差异，点估计一致。候选池偏向当时共同已完成的题，分层并不能消除全部选择偏差，不能代表独立留出集或全量。

## 为什么Agent相对E2E的优势会改变

Agent允许分解问题、定向观察、联合比较和多次模型调用；这些机制可以增加有用证据，相比一次性E2E有潜在收益。历史CV664等轨迹显示过Agent答对而E2E答错，但这不是对所有机制的因果消融，也不意味着更多调用总有收益。

相对增益=Agent分数−E2E分数，两个量都改变。35B/Cross中PRO Agent44.21→直接Agent43.83几乎不变，E2E却28.37→20.54，于是Agent相对优势由15.84扩大到23.29pp；不能据此说Agent推理能力提高了7.45pp。

MVU的官方首字符评分尤其受答案表达影响。移后E2E与直接Agent的官方/稳健分：

| 模型 | E2E移后：官方/稳健 | 直接Agent：官方/稳健 | Agent−E2E：官方/稳健pp |
|---|---:|---:|---:|
| 9B | 42.94 / 51.93 | 46.82 / 46.82 | +3.89 / -5.10 |
| 27B | 48.21 / 51.08 | 57.84 / 57.84 | +9.63 / +6.76 |
| 35B-A3B | 39.75 / 48.93 | 49.88 / 48.90 | +10.12 / -0.03 |

稳健分仅用于诊断明确答案提取的敏感性，不从reason猜答案，不替代论文官方主指标。尤其35B/MVU的官方优势不能全部解释为视觉或推理能力优势。

## 样本波动与真实失效需要分别判断

- 同题逐token确定不消除题目抽样误差。固定seed只固定所抽面板，不保证该面板代表全体题目。
- 126条旧小测只有共同随机32题/模型，CV15、MVU8、Cross9。扩大到每benchmark100题后，9B/CV的直接−独立点估计从-9.70变为+5.78pp；小面板确实容易翻转。
- 900条不是每个比较单元900题，而是3模型×3benchmark×100。许多差值区间仍有约±10pp宽度。最新144次调用也不是144道独立题，仅三个不同题目的重复完整运行和兜底，不能用来排名准确率。
- 但此前9B在5081道共同题中出现905个仅`}`答案，且H200中间批已有同类大规模异常，这是有直接轨迹证据的协议失效，不能用“小样本浮动”解释掉。它们多为合法JSON自然stop，并不是统一token预算不足。
- 前一轮直接协议使9B同300题格式错误71→7、仅`}`40→0；刚恢复的独立兜底在CV664又两次自然结束输出`}`。格式问题与推理可复现性可以同时存在。

## 同一改动对不同模型的效果

下面是前一轮“直接回答−独立回答器”的变化，单位百分点，题目在三模型之间完全相同。

| 模型 | CVBench | MVU | Cross九类 |
|---|---:|---:|---:|
| 9B | +5.78 | +10.76 | +3.17 |
| 27B | +7.09 | -1.06 | -1.91 |
| 35B-A3B | -1.60 | +3.94 | +12.34 |

点估计的方向和幅度确实不同，不应只用9B筛选所有模型的方案；反过来看，MVU中独立回答器相对直接回答是9B-10.76、27B+1.06，但后者区间跨0，不能当作已经证实的收益。此矩阵也没有证明某同一方案在整体上同时伤害9B、提升27B和35B。

直接比较两模型的“收益差”，而非比较各自显著与否：MVU的27B−9B为-11.82pp，95%区间[-24.56,+0.78]；Cross的35B−27B为+14.25pp，区间[+0.10,+28.57]。九个探索性模型对比中仅后者区间勉强不跨0，未作多重校正且边界接近0；不足以宣称已建立普遍的尺寸规律。

一种可能机制是不同模型对相同长指令、取证路线、证据冲突和结构化终答的适应不同：额外回答可能帮某模型重新判断，却让另一模型丢失既有结论或交付失败；增加步骤可能带来证据，也可能放大错误报告。这里只提出可测假设，不能仅由分数证明是参数量或某条Prompt导致。应比较具体模型，不把三个名字当作严格单变量的规模实验。

## 同题反向效果与收益位置

补充诊断CPU `ap-JsJXhihpVCezReeBoWB4I5` rc0，只读取已评分的900条配对，保存`diagnostics.json`和分析源码；分组贡献之和逐项等于总分差。

## 后续判断方式

保留用户已确定的System、FFmpeg、History与独立兜底。新的准确率实验先测这套实际源码，不能复用旧900结果作同协议基线。后续候选逐项改回答门槛/结论一致性、确有证据受限的字段或结构化生成路径；不一次混改数值后端、Prompt和媒体。

候选首先在三模型相同的分层60题（每benchmark20）上比较；允许先跑一个模型作为运行检查，但不能仅因9B准确率下降就取消27B/35B测量。分别报告每模型×benchmark的配对差值、格式和空答案、主动/强制结束以及最早证据分歧；有收益的候选再扩300。最终选统一方案时不能用大模型平均收益掩盖9B损失；若研究模型专属方案，需明确披露适配和选优预算，并用独立留出题验证。

本次没有修改正式配置，也没有启动后续候选实验。旧源码对齐证据与用户确定的修改见[实验计划](../pro6000_source_review_20261015/experiment_plan.md)，最新功能冒烟见[兜底报告](../terminal_answer_20261016/README.md)。
