## 当前判断

1. **有一部分是被上限打断了尚在推进的比较。** CV376是直接例子，不能一律缩短reason或移到结果后面。
2. **另一些是在上限之前已无法处理证据与选项的冲突。** Counting88和两条旧终答的续写证明，延长预算会继续重复，甚至无法产出完整结构。
3. **两种情况可出现在同一条reason里。** CV376先重复，后面才出现更有用的风险比较；简单遇到重复就停止也可能丢掉有用内容。
4. **自然结束和格式合格仍不足以证明收敛。** TR1398旧自然版本的理由排序与答案选项不一致，就是反例。

因此本轮不建议直接取消全部字符限制或继续扩大默认token上限。保留reason在前和有限总预算；
后续若做稳定性改动，应同时检查完整结构、题目要求、理由与结果一致性及准确率不退步，不能只看是否stop。
没有新增的通用运行时修复通过验收，正式默认保持不变。

## 限制

- 这批是反复使用的开发诊断题；不能保证所有输入、其他模型或非空skill下的行为。
- 没有新增视觉证据或重新看视频，不能断言是原摘要错、题目错，或模型能力已达到上限。
- “新比较/纠错”描述可见文本进展，不证明准确率提高，也不证明理由忠实反映内部计算。
- 字符上限取消时，原Prompt里的1200字符简洁要求仍保留，以隔离结构化解码限制；不等于所有长度提示都取消。
- 不评正确率、不做新配置重复性验收、不修改正式配置；自然结束、JSON完整、遵循题目、理由与结果一致分别判断。
