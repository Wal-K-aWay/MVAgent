# 三模型统一旧9B src＋FFmpeg：结果分析

用户已授权补跑27B失败题，当前独立补跑状态见[补跑记录](recovery_27b.md)；下文保留补跑前的分析口径。

2026-10-16。结论：不支持把这套完整旧源码直接定为三模型唯一方案。9B的CV/MVU点估计提高但格式更差；35B的CV/MVU提高、Cross下降；27B的CV下降更明确。

本轮三模型都用**PRO6000的9B源码快照**，不是分别恢复三份不同的旧源码。105个src文件相同，唯一相对原9B快照的源码变化为media.py改FFmpeg。历史27B/35B使用不同的schema、字符限制和结构化生成路径，所以本实验不是其原设置的逐位复刻，也不是FFmpeg单因素消融。

## 格式与工程可靠性

| 模型 | 独立回答器格式不合格 | 上一轮直接 | 本次 | 有效回答中的空答案 / 仅右花括号 |
|---|---:|---:|---:|---:|
| 9B，300闭式题 | 71 | 7 | **15** | 0 / 0 |
| 27B，289有效闭式题 | 5 | 4 | **3** | 0 / 0 |
| 35B，300闭式题 | 14 | 8 | **4** | 0 / 0 |

各模型计数含CV431既有选项标签缺陷。格式不合格不等于JSON解析失败，例如9B在合法JSON里答Cannot determine仍不满足选择题要求。976份有效回答均非空、没有仅右花括号；27B另14份工程失败无可用答案，不能隐去后宣称每题都能答。

27B/CV存在10道上一轮直接答对、本次答错的题，例如CV421由B变A、CV703由D变C；这些都是合法选项。两臂CV格式不合格都只有1题，CV退步不能归因于新增格式错误或已剔除的服务故障。具体由哪条提示或取证策略引起，尚未做单因素消融。

27B失败链条：`crossvid:MOC:565`的一次短视频观察元数据为1.1秒/11帧/10fps，计划解码两帧，其中frame10读取失败，实际只剩1帧。Qwen预处理抛出`ValueError: t:1 must be larger than temporal_factor:2`，同步后端随后退出。原请求及此后同卡13题最终收到503/Connection refused；其中3道CCQA触发Judge前置断言。

这属于媒体预处理与服务恢复边界问题，不是reason超限、答案格式或H100显存不足的证据。缺帧尚未隔离到裁剪器或解码器的具体实现，不能直接认定FFmpeg本身错误。

9B用16卡，27B/35B各8卡，且27B剔除故障题，不直接按整体墙钟比较速度。27B NC1001耗时32.02分钟/47调用，CV831耗时21.89分钟/30调用；35B CV736耗时16.54分钟/26调用，有效回答不代表过程高效。

27B有效316题的详细调用核查有3840响应、69次输出触顶、14题轨迹记录中间问题。这不包含14条顶层失败中的调用，不能将有效组的HTTP错误0解释为整批无服务故障。9B此前完整核查为103次触顶/26题；CV824反复生成相同无效视觉结果，最终Cannot determine。同题27B答A、11.25分钟，35B答A、约76秒；同一源码仍会产生不同取证路线和长尾。

27B的NC1001有15次触顶，观察器反复按时间罗列人物互动但JSON未闭合；CV831有10次触顶，反复列举跑步时间段，轨迹记录了“没有产生有效观察”后达到VideoAgent步数上限。这些问题发生在视觉报告，不应全部归因于GlobalAgent的reason；放宽所有字段上限并没有消除循环。

## 建议与验证边界
