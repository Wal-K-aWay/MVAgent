# 扩大 E2E 与长程 MVAgent 一致性测试

2026-10-12 完成。三模型在固定输入协议与 固定执行配置下，已测重复比较全部一致。
只比较完整 token、输入及轨迹，不评正确率、不调用 Judge。有限测试不构成任意输入或环境的数学保证。

8道长任务是66题的子集，不能把重复运行数当作不同题目数。

- E2E 另有9个冒烟响应和24个历史输入响应，主审计共3993次真实响应，全部与服务端完整token/请求SHA/进程/GPU/模型对象/forward记录精确匹配。
  这些当前配置响应按完整输入分组另得2997次比较，0差异；每模型332个不同输入组合。9个冒烟与对应正式题均一致。

  **含两次补测后，三模型每道题都有实际跨卡对照。** 主四轮计数与计时保持不变；总实际E2E响应为3995。
- 三模型服务重启后的resume均通过：原始输出文件和模型请求计数不变。
- 与旧固定配置每模型33个锚点比较，共99次全部一致；已核对权重元数据与执行配置，旧/新GPU UUID集合均无交集。
  这是一组实测跨分配证据，不能推广任意硬件或版本。

9B的37次调用来自 TR:1467（3730输出token），10152输出token来自 Comparison:818（33调用），不能合并成同一条轨迹。
27B的 Comparison:818 为28调用/9170token，四遍均自然结束且完整一致。35B两个最大值也来自不同样例。
提高步数上限不等于实际达到该上限，本报告按真实轨迹长度计数。

所有完整Agent运行均无模型错误或结构化校验失败；但9B有8次调用、27B有4次调用达到原2048输出上限，截断位置和完整输出也一致。
对应9B的 Comparison:818 每遍两次调用、27B的 MOC:521 每遍一次调用。额外长程面板的1580次调用全部stop。
E2E中35B有16条、9B有12条响应达到各自原输出预算，27B全部stop；预算没有为通过测试而调整。
9B的Agent样例 cvbench:664 最终answer字段仍为右花括号：输出一致不代表格式合格或答案正确。

## 固定配置与输入协议

- 8个独立H100副本，每副本TP=1、DP=1、并发1，三模型统一BF16；标准加载器、同步inproc/eager。
  FlashInfer GDN prefill、native GemmaRMSNorm，显存比例0.94、expandable segments；prefix/MM缓存关闭，正常解码KV开启。
  seed=0、temperature=0、thinking关闭，context131072、prefill32768。
- Agent诊断与E2E共用ENGINE_CONFIG和ENVIRONMENT（实现现位于[共享同步服务](../../src/models/vlm/local/sync_server.py)），未改变权重、提示、动作或结构化验证。
  每题内部固定副本，CPU Video并发2，实际模型调用串行；同进程乱序两遍后，重启并将分片GPU轮换，再两遍。
  Agent使用完整原运行时与进程内队列传输；**正式在线HTTP Agent入口、题内逐调用换副本及非空skill不在本轮验收范围内。**
- E2E使用原 run.py infer / --endpoints / --ids 接口，512帧/448、官方提示与生成预算不变。每次都重新执行模型forward。
  四遍均从已独立核验的固定帧缓存重建请求，每个输入SHA必须等于冻结参考；不缓存模型答案。
- 新增题按seed20261012分层抽样，保留旧33题，不按正确率筛选；CrossVid限定Lite2500，排除已知截断源视频涉及的CV64–66。
  反复使用的面板均为开发集。

## 输入准备的负结果

两次独立视频准备的330题输入SHA全部一致，见[输入准备审计](input_preparation.md)。
但它们与最初16-worker冷解码运行比较时，CCQA:151 和 FSA:192 两题输入SHA改变，帧数与尺寸不变。
新两轮及额外串行重复均一致；旧运行未保留完整图像请求，无法定位旧差异具体来自哪一帧，原因仍未确定。
这两题不能作为“完全相同模型输入却输出不同”的反例，也不能据当前固定帧结果宣称原始视频冷解码已全面稳定。

因此，当前可采用的是**冻结并核验实际帧输入的评测协议**。视频准备的重复性与模型推理重复性分别报告，
论文计时时应单列一次性输入准备成本，不能把下面的缓存测量写成包含冷视频解码的完整工期。
