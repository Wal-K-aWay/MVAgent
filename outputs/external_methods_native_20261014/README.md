# 原分辨率、原帧率拼接设置

用户要求只取消拼接预处理中的缩放及FPS转换，保留模型输入的既有限制。后续仅评测Video-RSI和VAM，Meta不再提交。

- 同题全部为H.264或全部为MPEG-4 Part 2时，通过视频码流复制拼接，不重编码；不同片段保留不同分辨率和帧率。
- 混合编码或其他编码时，先逐段统一为H.264无损编码（libx264、QP 0），再复制拼接。同题所有片段使用相同转码路径；不缩放、不填边、不补帧/抽帧，不自动旋转。原像素格式不能保持时明确报错，不自动降低位深或颜色采样。
- 统一容器时间刻度到微秒，不改变每个片段的帧时间间隔。每段以首个视频包的PTS归零，并在拼接后核对完整视频包PTS序列。
- 时间范围以实际视频包计时；原始容器可能包含音频尾部或提前开始的音频时间，不能直接用容器总时长作为下一视频偏移。
- prompt首先说明这是多视频理解任务、原视频已按顺序拼成一个完整视频，再列出各段起止时间和原时长，均显示两位小数。原问题与选项保持原样；题目和答案仍用原视频相对时间。标签独立保存，内部时间元数据不舍入。
- 本轮沿用旧33题manifest，不重新抽样；媒体与元数据仅留Modal。新目录为`devbox/external_methods_native_20261014/`。

合成CPU检查已验证H.264与MPEG-4的混合尺寸/帧率输入，50/50帧的解码像素、尺寸和时间不变。实际33题已在`prepared_r2`全部准备完成：R1因容器时长和视频包时长不一致被拒绝，失败材料保留；R2改为逐包计时和校验，没有用重编码绕过。

此前准备的33题在每题内编码一致，使用的是直接复制路径。最新混合编码分支增加逐段及最终文件的流式解码核对：帧数、尺寸、像素格式、RGB像素哈希和时间戳必须一致，并核对片段总时长；manifest记录处理方式和完整命令。无损转码会增加CPU耗时和磁盘占用。当前模型侧设置未改变：RSI抽帧宽度448；VAM图片面积上限448×448，仍按其原流程抽帧、生成记忆及检索。

没有将旧33题模型输出当作新预处理结果；当前改动验证的是媒体准备与提示词组装，尚未在新媒体上重新测模型准确率。

最终媒体核对：33题沿用相同manifest，359515个视频包计数/PTS通过；3道真实混合输入的16次分段跳转均保持解码尺寸、RGB像素和对应时间。远端完整compileall及合成50帧/4次跳转检查通过。这些检查在用户要求不再实际测试之前已完成。

上述历史验证仅覆盖同编码直接复制。混合编码与可变帧时间用例最初遵照用户要求未执行；用户随后重新授权测试，修复远端旧FFmpeg参数兼容问题后，四组合93帧/8次跳转通过。两个方法的新协议实测独立记录在[当前小测报告](../external_methods_current_20261014/README.md)，不与原33题结果混合。

按用户最新指令，不再启动实际测试或推理。本轮仅供审阅输入；示例见[prompt_example.md](prompt_example.md)，共同question用已准备样本的元数据套用最新两位小数模板，系统模板来自冻结源码，动态证据字段明确以`<runtime ...>`标示。远端冻结的`prepared_r2`仍保留原提示文本，未覆盖历史输入，也未用本次新措辞运行模型。

输出格式：当前RSI适配版的`answer`与VAM原生的`response`均接受非空字符串；框架控制消息用JSON，最终答案可以是单选、多选、排序、时间区间、数值或自然语言，具体按原题要求。RSI发布版原本只接收一个实际选项，该限制已由适配补丁放开。格式接口支持不等于模型一定遵循格式或答对；本次只核对代码，没有新增实测。
