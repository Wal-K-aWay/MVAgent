# PRO 6000 与当前 MVAgent：同题、轨迹和协议分析

统计快照：2026-10-15 15:34–15:35 北京时间（07:34–07:35 UTC）。本次只做离线分析，未修改代码、Prompt、schema、推理参数或已有结果，未启动新推理或 Judge。当前全量评测继续使用冻结源码。

## 结论

9B 的退步在同题比较后仍然成立。主要可见损失是最终答案交付失效：在 5081 条闭式共同题中，905 条答案只有 `}`，1457 条不能按统一的保守提取规则读出答案。905 条 `}` 的日志响应全部是合法 JSON，`answer` 值确实为 `}`，全部自然 `stop`，输出中位数仅 120 token。不是解析器把答案误删，也不是这 905 条都耗尽 2048 token。

独立回答器是故障明显集中的环节：有实际案例在决策理由、最终理由中都确定了正确选项，最后却提交 `}`；也有回答器重新解释问题、推翻前一步判断而拒绝选项的案例。但新旧同时改变了模型服务、媒体处理、Prompt 和回答协议，没有固定相同证据做消融，不能断言“独立回答器单独导致全部分差”。

27B 大体保留了旧 Agent 水平；35B 的 CVBench/MVU-Eval 接近旧水平，CrossVid 暂有下降，但仍超过同题当前 E2E。27B/35B 的当前答案可提取率明显高于 9B。同一套协议对三个模型的影响不同，不能用少量 35B 小测替代 9B 的格式验收。

旧 H200 中间批次同题已经出现 1023 条 `}`，9B 稳健分与当前接近。因此，最近的 H100 固定配置、最终 reason 放宽及最新 System 不是此问题首次出现的必要条件。稳定复现只保证相同输入产生相同输出，错误格式也会稳定复现。

## 4. 实际轨迹：独立回答环节引入了什么差异

### MVU-Eval Comparison:1232，9B：理由正确，交付错误

问题比较左前、正前、右前三个视角共同出现的对象；正确项 A 是草坪、树、橙红色路障、工人与机械。

- 旧 Global 最终决策：reason 471 字符，说明联合观看支持 A；同一条生成中直接给 `parameters.answer = "A"`，答对。
- 当前 Global 最终决策：明确写出 “Option A” 且证据已充分，然后 `action=answer, parameters={}`。
- 当前独立回答器：理由再次写出 “The final analysis in Event 4 supports Option A as the intended answer.”，但 JSON 的最终字段是 `"answer":"}"`。
- 该终答 127 token，`finish_reason=stop`，JSON 完整，Runtime 原样接受；旧/新 E2E 也都答对。

这里不需要假设视觉能力下降来解释该条失分：当前回答器自己的理由已经选择了正确项，失分发生在提交最终字段时。日志未证明 `}` 来自何种内部 token 偏好或 grammar mask，因此不能把它直接归咎于 FlashInfer，也不能断言单改一个示例即可修复。

### CVBench:712，9B：重新判断后拒绝给选项

题目问哪种动作在所有视频中被“提到或展示”，A 为使用榨汁机。

- 旧 Global reason 4752 字符，比较三个视频并排除其他选项，最后同一条生成提交 A，答对。
- 当前 Global 明确指出视频 1 的文字提到了 “using high-quality juicers”，视频 2/3 展示使用；认为已有足够证据，无须继续观看。
- 独立回答器重新强调视频 1 只有静态文字、视频 2 处理肉而非水果，输出 `None of the options are consistently shown or mentioned across all videos.`。
- 当前终答仅 145 token，自然 stop；没有触及预算。它没有延续前一步对“提到或展示”的理解，而是拒绝题目要求的选项。四方中只有当前 Agent 失分。

新旧观察报告并非完全相同，不能把全部差异孤立归因于回答器；但当前流程内部从前一步证据解释到最终拒答的变化是直接可见的。

### CVBench:664，9B：同一协议也能正确完成

比较盆景整形视频使用的共同工具，旧/新 Agent 都答 B（修枝剪）。当前 Global 判定证据充分，独立回答器 66 token 自然结束并提交 B；当前 E2E 错误。这说明独立回答器并非必然失效，Agent 的取证收益仍然存在。

### 与空答案案例区分

27B KIR:471、35B PEA:555 的旧结果本来也答错；当前变成两次 2048 token 截断后的空答案。它们证明交付方式发生退化，但不能拿来证明“旧正确→新错误”的准确率下降。完整失效路径见 [12 条空答案审计](empty_answers_20261015.md)。

## 5. 回答协议、Prompt 与限制的核对

| 项目 | PRO 6000 旧结果 | 当前冻结运行 | 含义 |
|---|---|---|---|
| 最终回答 | Global 的同一条 decision：reason/action/parameters.answer | decision 先选 answer，parameters 为空；另发 global_answer 请求 | 增加一次重新判断及最终字段生成的机会 |
| 决策 reason 的传递 | 最终答案续写在同一条决策生成中 | 最终回答只收到 question+公开 History，不含上一条正常 decision reason | 前一步判断不是回答器必须保留的上下文 |
| 每次完整输出 | 三模型均 2048 token | 三模型均 2048 token | 不是统一缩小总预算导致退步 |
| 普通决策 reason | 9B 旧实际输出可远超1200；27B/35B 终答决策均不超过1200 | 1200字符 | 旧三个模型并非完全相同协议 |
| 当前终答 reason | 旧9B有长终答决策；旧27B/35B实际最大1200 | 无字符硬限，仍受2048总token限制 | 对不同旧基线的变化不同 |
| 采样 | temperature=0、top_p=1、thinking关闭 | 相同；固定seed=0 | 不是本次把随机采样改坏了；旧seed记录未据此补造 |
| 行动与视觉预算 | Global/Video各5步，512帧，每请求最多8视频 | 相同 | 不能把本次退步解释成统一减少步数或帧上限 |
| 服务 | dtype=auto；context262144；9B四副本×并发2，27/35六副本×并发1 | BF16，context131072；8个独立TP1/DP1、每卡并发1 | 硬件、内核及实际媒体处理仍是混杂项 |
| 等待与重试 | 9B 300秒、27/35 120秒，max_retries2 | HTTP1860秒，max_retries1 | 超时边界不同；不能解释正常stop的905个`}` |

对三条代表题的实际 `global_answer` 请求核验：只有 system/user 两条 message，均不含上一条完整 decision reason。冻结 `GlobalAgent.answer()` 使用 `question` 与 `memory.render_action_history()`；Global memory 记录取证参数、报告和反馈，不记录成功决策的 reason。reason 在日志轨迹中可见，不等于它已传入下一轮模型。

当前终答请求的实际 schema：reason 为非空字符串且无 maxLength；answer 为非空字符串、maxLength2400，没有合法选项枚举。多数问题因此是“JSON结构合法、任务答案不合格”，不能统称为 JSON 解析失败。

旧 9B 共同题终答 reason 最大为 CV 8311 / MVU 7523 / Cross 7897 字符，共 403 条超过1200。旧27B/35B最大均为1200。这是从实际输出确认的差异；未取得旧schema，不能反推每个旧版本的完整schema定义。旧9B终答平均reason还略长于当前，不支持“现在所有理由普遍更长，所以9B退步”的笼统解释。

### Prompt 能确认的变化和不能恢复的内容

当前冻结 Prompt 已包含明确约束：决策要求一到两句、核实证据冲突、避免重复论证；终答要求依据证据作最佳判断、不能用缺证据讨论替代结果。终答 User 也明确要求选项题在 answer 中只放标签或题目要求的选项文本。因此不能诊断成“完全没写答案格式要求”。这些要求仍未阻止上述 9B 异常。

当前 System 文本精确抽取并保存：decision 172 words，answer 188 words；最终 User 模板150 words。仓库初始快照 `5f8d246` 已有独立回答器及简短 System，例如 `You are the final answerer for a multi-video question...`；它不是 PRO 6000 原源码，不能冒充旧 PRO Prompt。

旧便携包中保留了答案、轨迹、配置和 manifest，但未保留完整原始请求 Prompt/schema/响应 token 日志；9B events 文件为空，27B/35B compact events 去除了正文。旧提交分别为9B `cfce76ce292e68762a0e392560058905bd820327`、27B `c48060fc3f791e8c42e595b59f22481653567b4d`、35B `bfb6c7363e1dd42a5d1f3b951a077bcff5a740b3`，当前仓库对象库未找到。故本次不能给出旧 PRO 与当前 Prompt 的逐字 diff，也不能把三个旧模型视作同一源码协议。

## 7. 可以判断与尚不能判断

可以确认：9B有大规模最终字段交付问题；独立回答新增了一次不携带前步reason的判断；它可能正确解释后错误提交，也可能重新判断后拒绝任务格式。主要异常不由耗尽2048预算解释，少量循环截断和旧传输错误是另外的失败类别。27B/35B对同一当前协议适应明显更好。

不能确认：是哪一条Prompt、哪一处JSON约束、哪个kernel单独造成`}`偏好；移除独立回答器是否一定提高总分；恢复长reason是否不会损伤动作选择。取证路径和观察内容也变了，双方可提取组仍有退步，不能把一切归为格式。

若后续验证因果，最小且有区分度的实验是固定同一批已冻结问题与证据，对比旧式同次决策提交、当前独立回答、独立回答保留决策摘要三个调用条件，同时记录格式和正确性；单独控制reason上限，不能把硬件、Prompt、预算一起改变。本次没有执行这些实验，也没有新增答案枚举或改变架构。
