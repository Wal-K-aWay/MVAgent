# GlobalAgent Skill 自进化流程

本文是当前实现与目标设计的工作说明。简要解说沿用原流程的叙述方式，详细章节定义输入输出、调度、验收和恢复边界。

**实现状态：**当前 `global-skilladaptor-v1` 已实现固定 Train 输入聚类、跨 batch 素材池、Localizer、Linker、Generator/Reviser、逐候选完整 Gate 及轮末提交。固定父库的 batch 汇总更新、embedding 局部 Gate、阶段性完整 Gate 检查点及回滚均为目标设计，尚未实现；Merge 也未实现。本文不改变 Runtime、Prompt、Schema 或现有实验。

当前仅优化 Global Skill，Video Skill 冻结；不实现外层交替调度，不自动执行 Test。

## 1. 简要流程

有一个训练集和一个 Gate 集，两者题目 ID 无交集。视频来源是否隔离由具体 split 和来源审计决定；训练不读取 Test。

训练开始前，根据全部训练题目的**完整问题、选项、每个视频的 ID 和对应时长**提取 embedding，使用 Louvain 聚类。同一次训练的分组固定，孤立题目保留为单例。

对 Gate 题目使用相同输入格式和 embedding 模型提取向量，根据与训练簇中心的 cosine 相似度分配到最近的簇。每簇 Gate 清单、相似度阈值、最低题量和邻簇补题规则在训练开始前冻结；相似度不足的题目不强行归入。Gate 不参与训练聚类，也不进入素材池。用初始 Skill 库运行完整 Gate，保存完整验证检查点。

从训练集中随机抽取一个 batch，全部题目使用当前 Skill 库运行：每道题最开始选择一张 Skill，或者不选；之后整道题始终使用这次选择的 skill。运行完成后评估正确性。本批处理期间 Skill 库固定，全部建议基于同一个父库。

将运行正常的成功和未完全成功轨迹保存到对应簇的素材池，记录当时的库、实际 Skill 和运行结果。只将健康且未达到定位阈值的题目交给 Localizer，分析有依据的错误链、原因和改进原则；无法定位时返回 skip。正式 Localizer 仍输入 selected Skill。

对每个成功定位的失败案例，从同簇已运行的题目中选取**最多 4 条参考轨迹**，优先成功、未完全成功各 2 条，再用可用近邻补足。参考可以来自之前的 batch；同一题只贡献最新版本，不必等待两类案例都齐全。旧库案例明确标注版本，不直接作为当前 Skill 缺陷的证明。

对于当前错误步骤：

- 没有使用 Skill，直接进入 Generator。
- 使用了 Skill，由 Linker 判断该卡是否存在与错误有关的内容缺陷。有依据则进入 Reviser，否则进入 Generator。未遵循已有指导本身不证明卡片有错。

Generator 根据当前题目、错误定位和同簇成败案例提出新 Skill。Reviser 额外输入目标卡和修改理由，保留有依据的有效指导、补充缺口。两者不输入整库。**簇提供素材，不固定对应一张 Skill；成功也不自动归功于所选 Skill。**

程序检查候选格式、长度、ID 和完全重复等约束，将本批有效建议汇总为一个候选库。同一张卡只保留第一个有效修订，不部署中间版本。根据有效建议来源簇对应的冻结 Gate 清单选取相关题，再加入固定跨类型回归题，构成本批局部 Gate；相关题不足时按 embedding 近邻补题，仍不足则使用完整 Gate。

父库和完整候选库从头运行同一局部 Gate，正常选择 Skill。新建或修改只有局部官方聚合分数严格提高、回归题逐题得分不下降、没有新增 fatal/invalid 才接受；持平或下降则拒绝。训练 batch 的分数提升不替代独立 Gate 验证。Gate 题目、轨迹和详细评分不提供给作者模型。

接受后一次更新当前库，下一 batch 使用更新后的库运行；拒绝则保留父库。本批错误处理始终基于父库，不因中间提案重新运行、评分或定位。历史参考无需全部重跑。

**计划中的 Merge** 放在 batch 错误处理结束后：每批最多检查一对相似卡，一次模型调用判断并生成合并卡。两卡合一纳入本批候选库，并将来源卡关联簇的 Gate 题纳入局部验证；无法确定来源簇时使用完整 Gate。仅 Merge 时总体及逐题得分不下降、没有新增 fatal/invalid 才接受；与新建或修改一起提交时仍要求局部总体严格提高，否则保留父库。

原子保存当前库、本批素材更新、局部验证结果和处理状态，进入下一批。恢复时校验素材哈希并重建跨 batch 素材池，同时恢复局部 Gate 映射和完整验证检查点。

每个预先声明的训练阶段结束后运行完整 Gate，与上一个完整验证通过的检查点比较。期间包含新建或修改时，官方总体分数严格提高、没有新增 fatal/invalid 才保留；期间仅有 Merge 时，总体及逐题得分不下降、没有新增 fatal/invalid 才保留。通过则更新检查点，否则恢复检查点库；历史素材保留并标注原库版本和回滚关系。

训练结束前完成最后一次完整 Gate 验证，最终输出完整验证通过的库。最终独立 Test 评估另行运行。

## 2. 入口、模块和数据边界

训练入口使用显式冻结的 split manifest，`eval` 分区作为 Gate；Train/Gate 均非空且题目 ID 无交集。训练不加载 Test。来源隔离以具体 split 和媒体来源审计为准，不能由 ID 无交集推断整片或会话隔离。

| 模块 | 职责 |
|---|---|
| [trainer.py](trainer.py) | 当前采样、逐候选验证、轨迹刷新及提交；目标 batch/阶段调度在此接入 |
| [question_groups.py](question_groups.py) | Train 原始输入 embedding、Louvain 分组和同簇素材检索 |
| [evidence.py](evidence.py) | Global 公开案例、选择与实际注入审计、历史版本关系和模型输入渲染 |
| [stages.py](stages.py) | 阶段调用持久化、Schema 校验、操作路由及候选库构造 |
| [prompts/](prompts/) | 各阶段 Prompt 和输出 Schema |
| [chinese_prompts/](chinese_prompts/) | 模型可见 Prompt 的中文文档镜像，Runtime 不加载 |

每题从完整 bank 开始运行，Global 要求 `selection_scope: task`：题目开始选择一张卡或 none，后续普通决策复用选择。Selector 只依据原始问题、选项、视频 ID/时长及卡的 description/when_to_use；Actor 只接收 strategy。Observer 和 Runtime 终止收尾不直接接收 Skill。

初始 bank 可为空；候选只变更 Global 卡，Video 卡保持不变。Skill 是方法指导，不能成为事实证据。优化器只获得 Train 的 Global 公开视图，不获得 Video 私有轨迹或 Gate 反馈。

## 3. 固定 Train 分组与 Gate 映射

### Train 输入分组（已实现）

编码内容仅为完整问题、选项、按原顺序排列的每个视频 ID 和时长，不加入答案、正确性、轨迹、选卡、Localizer 输出或 benchmark 标签。视频时长来自媒体元信息，不调用视觉模型。完整 Train 在首次训练时统一分组，后续 batch 不重新聚类。

当前分组采用 mutual-kNN、cosine 阈值和固定种子的 Louvain，不预设簇数；无边题目保留为单例。当前具体参数以 question_groups.py 和 README 为准，不能将 Train 连边阈值直接复用为 Gate 分配阈值。

### Gate 输入映射（待实现）

1. 用同一模型、输入模板和归一化规则编码全部 Gate 原始输入。
2. 对每个 Train 簇的归一化成员向量求均值，再归一化为中心；单例使用自身向量，零范数中心标记不可分配。
3. 每道 Gate 题关联 cosine 最高的一个有效中心；同分按稳定簇 ID 排序。最高相似度低于运行前声明阈值时标记未分配。
4. 保存每簇 Gate ID、相似度、未分配清单、Train 分组哈希、输入与模型身份、分配规则身份。
5. 冻结每簇题目配额、最低题量、邻簇补题顺序及固定跨类型回归清单。配额抽样使用固定种子，不能根据候选分数选题。

Gate 不加入 Train Louvain 图和素材池。映射表示输入相似度，不证明共享同一种策略，也不证明其他簇不会选择候选卡。

**待确定的运行参数：**相似度阈值、每簇配额、最低题量、邻簇补题规则、回归清单及阶段验证周期。实现时必须显式声明、校验并纳入恢复身份；本文不提供未经验证的默认数值。

## 4. batch 调度与素材池

保持参考流程的随机 batch 采样。当前代码每轮用 `seed + round_index` 打乱完整 Train，再取前 batch_size 题，不保证不放回遍历。目标不得把“轮”静默改为 epoch；阶段性完整验证的周期另行声明。

batch 开始冻结父库及其哈希，全部题目从头运行并评分。本批定位、归因和作者建议都依据该父库；建议生成后不部署临时版本，不刷新本批剩余轨迹。

每题的最新健康案例进入同簇素材池；fatal/invalid 案例记录异常并移除其可用素材。成功和未完全成功素材都保留。运行失败不能伪装成 usable observation。

参考最多4条不同题目，优先成功/未完全成功各2条，再用可用同簇近邻补足；排除当前题，同题仅使用最新版本。历史素材记录原库、实际选卡及注入审计，允许跨 batch 使用，不要求两种结果齐全。成功不自动证明 Skill 有效；旧库失败不直接证明当前卡有缺陷。

## 5. 定位、归因与作者输入输出

| 阶段 | 输入 | 输出及约束 |
|---|---|---|
| Localizer | 当前题原始输入、selected Skill、Global 公开步骤、最终答案和离线参考 | status/reason/fault_chain；located 为1–3个可编辑步骤，skip 为空链 |
| Linker | 当前案例、错误步骤、实际使用的唯一卡、同簇参考 | status=revise/generate 加 reason；没有权重阈值或 skip |
| Reviser | 当前案例与定位、目标卡、修改理由、同簇参考、近期历史和拒绝候选 | 完整三字段 profile 或 skip；保留原卡 meta |
| Generator | 当前案例与定位、同簇参考、拒绝候选和长度约束 | 新 ID 及 description/when_to_use/strategy；程序补 meta |

Localizer 默认只处理健康且低于 issue_score_threshold 的题。selected Skill 仍是正式输入；选择记录与真实正文注入分别审计，缺失记录标记未知，不推断已注入。

公开案例移除 Global 决策及答案的 reason，保留行动、参数和返回证据。每步判断只依据行动前可用证据。Runtime 强制收尾不是可编辑步骤；故障类型不覆盖 Linker 的内容归因。

未使用 Skill 时直接 Generator。使用 Skill 时，只有可识别的卡片内容缺陷及其与行动或选卡的证据联系支持 revise；没有遵循已有指导、Localizer 的建议或潜在补救价值本身不能证明卡片有错。

作者不读取整库。每项定位保留初始链预算，不因提案生成新增预算。各阶段一次请求，先持久化后校验；无效输出记录并跳过对应工作，不追加阶段级纠错。传输、身份或评分错误传播为 operational error。

## 6. batch 候选汇总与 Merge

全部提案通过 Schema、角色/stages、非空字段、长度、ID 和完整库约束检查，并排除完全重复内容；没有额外语义 Validator。当前 max_card_words 默认5000，不能超过 Runtime 的5000上限。

按稳定案例/步骤顺序汇总：同一父卡只提交第一个有效完整修订，后续冲突记录后跳过；新 ID 冲突和完全重复同样保留首个有效提案。不拼接不同作者输出，不让后一个 profile 静默覆盖前一个。

有效建议统一应用到父库，形成一个完整候选库。本批整体接受或拒绝，拒绝后不逐卡拆分重试；整体拒绝不能说明每张卡都无效。没有有效变化且没有可用 Merge 建议时不执行局部验证。

### 唯一 Merge 入口（待实现）

Merge 只在 batch 错误处理和建议汇总后执行。检索拟提交库中的同 stages Global 卡，每批最多检查最相近的一对，稳定 ID 打破相似度并列。

检索向量使用 description、when_to_use 和 strategy；卡对身份使用两张卡的完整内容哈希。相同内容的已检查卡对不重复调用；模型判断缓存与是否部署分别记录。

一次模型调用只接收两张完整卡、action/卡片契约和长度限制，不接收整库或 Gate 反馈。输出 skip 或完整合并卡；具体 Schema 和合并 ID 规则待实现时定义。只有内容统一且有效独有指导可保留才建议合并，embedding 相似本身不是合并证据。

合并作为本批最终候选的一部分，程序原子删除来源两卡、加入合并卡；正式库只在整批接受后改变。Merge 的来源卡若已在本批修改，模型读取拟提交版本并记录来源哈希。

## 7. 局部 Gate 选择与验收（待实现）

### 选择验证题

相关题覆盖本批有效新建/修改的来源 Train 簇；Merge 另外覆盖来源卡已知关联簇。取冻结清单并集，加入固定跨类型回归题后去重。相关题与回归题交集仍具有回归保护属性。

不足最低相关题量时按冻结的输入近邻规则补题。仍不足、单例无法可靠分配或 Merge 来源簇未知时，退回完整 Gate；完整 Gate 验证使用第8节相应的严格规则。没有覆盖不能当作通过。

不能用作者 Train batch 验收，不能依据候选内容、答案、分数或轨迹动态改变清单。每批保存来源簇、最终 ID 顺序、补题和回退原因、清单与聚合规则哈希。

### 对照运行

父库和候选完整库使用同一题目清单、Actor、Selector、执行设置、评分协议，从每题起点运行。不强制注入候选卡，不拼接不同库的轨迹。父库仅可复用完整身份一致的结果缓存。

局部使用适用的官方任务评分和预声明聚合权重。题目只覆盖部分任务时，称为局部得分，不能宣称完整 benchmark 分数。不得在结果出现后调权。

### 接受条件

| 候选类型 | 必须同时满足 |
|---|---|
| 包含新建或修改，可含 Merge | 局部官方聚合严格提高；固定回归题逐题无损；全部局部题没有新增逐题 fatal/invalid |
| 仅 Merge | 局部官方聚合不下降；全部局部题逐题无损；没有新增逐题 fatal/invalid |

相关题允许得失相抵，回归题不允许；不要求每张新卡单独证明增益。没有成本、时间或 Observe 次数目标。健康差异按相同题目 ID 配对，不能只比较总计数。

缺失评分、非有限/越界分数、Judge 或执行失败属于 operational error，不计零、不当作持平或接受。本批接受后一次更新工作库；拒绝保留父库。

Gate 的问题、参考、轨迹、逐题和总体详细评分不进入 Localizer/Linker/Generator/Reviser/Merge。作者最多得到不含评分细节的拒绝记录；拒绝不等于内容缺陷证明。

## 8. 完整 Gate 检查点与回滚（待实现）

初始库运行完整 Gate，建立初始检查点。按运行前声明的 batch 阶段周期，对工作库执行完整 Gate，与最后完整通过的检查点比较，不与某个局部 batch 得分比较。

| 自检查点以来的操作 | 完整接受条件 |
|---|---|
| 包含新建或修改 | 官方总体严格提高，且没有新增逐题 fatal/invalid |
| 只有 Merge | 总体及全部逐题得分不下降，且没有新增逐题 fatal/invalid |
| 工作库与检查点内容相同 | 复用身份一致的完整结果，无需重复推理 |

包含新建/修改时，分任务和逐题得失记录但不增加全面逐题无损门槛。完整验证通过后推进库、分数、结果身份及检查点游标；不通过原子恢复检查点库。验证失败不推进检查点。

回滚不删除已运行 Train 素材，保留原库哈希和未通过 lineage；不能把它们视作恢复后当前卡缺陷的直接证明。回滚不倒退已完成 batch 游标，后续 batch 用恢复后的库重新运行，不无条件重新部署被回滚候选。

训练结束或正常提前停止前，尚未完整验证的工作库必须完成完整验收。最终输出最后通过检查点的库，可能是初始空库；局部通过的工作库单独保留审计。完整 Gate 是反复用于选库的验证集，独立 Test 另行运行。

## 9. 状态、缓存与恢复

目标需要原子保存以下状态，具体新产物路径待实现时确定：

- batch 父库/候选库哈希、有效操作与冲突记录、作者阶段结果和处理游标。
- 本批素材更新、异常移除清单、文件路径与内容哈希，用于恢复最新跨 batch 池。
- 冻结 Train 分组与 Gate 映射、验证清单/权重/规则身份、对照结果和接受决定。
- 工作库与完整检查点库的独立身份、阶段游标、检查点以来操作类型及回滚记录。
- Merge 卡对内容版本、模型判断缓存和实际部署状态。

提交 batch 和推进/恢复完整检查点各自作为原子提交点。重启不能把局部工作库误认为完整通过库。已提交 batch 不重复运行，未提交阶段按完整身份复用持久化响应和评估缓存。

恢复校验源码、输入/split、媒体、初始库、模型/执行/评分、Prompt、embedding、采样及验收规则身份；任一变化不能静默复用旧运行。使用非阻塞训练进程锁。素材缺失或哈希变化中止，不悄悄重建不同内容。

## 10. 实现与验证清单

后续实现应先确定局部 Gate 参数和阶段周期，再接入固定映射、batch 汇总、单批对照、工作库/检查点双状态和原子回滚；Merge 使用同一批末候选入口。

CPU 验证应覆盖：无标签泄漏、稳定映射/同分/单例/零中心、题量不足回退、回归交集保护、同卡冲突、同批固定父库、严格增益与纯 Merge 无损条件、逐题健康比较、评分失败、素材哈希、阶段回滚及中断恢复。没有真实训练结果前，不宣称节省了多少成本或提高了泛化分数。

本文修改仅为文档设计，不新增配置字段、不改变模型可见 Prompt，故不改中文 Prompt 镜像。实现 Prompt/Schema 变化时必须同步对应 chinese_prompts 文件。

当前 Skill 长度规则：三个文本字段合计最多 **1200 words**，description 最多60 words，when_to_use 最多120 words；渲染正文（含标题）最多1200 words。统一由 `count_words` 统计字母/数字/下划线组成的词，词内撇号和连字符不拆分，独立标点不计数；cat、analyze_videos、segment_1 各计1 word，1->2 计2 words。这是英文词计数，不是 tokenizer 或中文分词。Prompt 要求简洁英文，通常900–1100 words或更少，上限不是写作目标。配置改为 max_card_words/max_skill_words；旧字符配置不再支持。JSON Schema 仅保留非空和结构检查，单词上限由程序统一校验。冻结实验仍保留原字符口径，不能混用新源码恢复。
