## TASK

# Skill 生成

将已校验的 NEW 计划实现为一个可复用的完整问答 Skill。遵守共享 Skill Card Specification，不重新决定操作或卡库归因。

## 输入及其作用

- **plan**：方法缺口、目标、证据引用和应保留行为，定义拟实现能力。
- **issue / cases**：分析及原始开发证据，用于核对假设并形成可执行规则；参考答案是离线反馈，不是视觉证据。
- **library_catalog / related_cards**：已有范围与方法，用于避免重复。未使用或未遵循充分指导不等于缺少方法。
- **variant / earlier_edits**：候选序号与同计划已有候选，是提案，不是观察结果或拒绝原因。
- **max_card_words**：共享规范定义的组装整卡总 word 预算。

## 生成要求

1. 从原始输入提取可识别的任务类：必要输入关系、主要任务和答案内容。移除偶然题材及案例答案。
2. 将方法写成完整编号过程：初始证据获取、返回证据如何支持任务、必要追问的可观察条件、足以 answer 的证据条件。
3. 将实质修复放在对应决策处，说明信息、动作和参数/指令来源。追问针对具体未解决缺口，不重复原样请求。
4. 核对 when_to_use 与 strategy：用途表达实际支持的任务，策略无需读取用途即可执行；保留计划支持的成功行为与任务区别。
5. 若存在 earlier_edits，提供同一计划内实质不同且有依据的候选；只能换措辞或提出无依据方案时 skip。

事件计数方法可在计数请求中定义完成事件、获取带时间的事件列表，再依据争议事件区间和完成线索复查。“仔细计数”没有提供该方法；把训练答案或偏好选项写入卡不能实现计划。

## 阶段约束

- 使用背景中的可用动作和信息边界；指令依赖来自输入或之前返回结果。
- 不扩大计划能力、不编造观察、不修改其他卡。
- Agent 未遵循充分规则时，不用重复该规则代替实质改进。
- ID、role、stages 由程序分配，不输出 metadata 或额外内容字段。
- edit 是候选，不是已接受改进；Gate/Test 证据不可用。

## 输出格式

仅返回符合 Schema 的 JSON 对象，不加 Markdown 围栏或额外文字：
- **status**：edit 或 skip。
- **summary**：实质变化及依据，或跳过原因。
- **when_to_use**：edit 时为非空英文任务范围句；skip 时 null。
- **strategy**：edit 时为完整非空英文编号过程；skip 时 null。

只输出这四字段。JSON 字符串内的换行用 \n 转义；无法以有依据的方法落实计划并满足共享规范时 skip。
