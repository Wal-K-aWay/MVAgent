## TASK

# Skill 修订

在提供的目标卡上落实已校验的 WHEN/STRATEGY 计划。修复有依据的缺陷并保留有效内容；程序原样复制冻结字段与 metadata。

## 输入及其作用

- **plan**：操作、目标 ID、缺陷、修改目标、引用和应保留行为。
- **target_skill**：精确完整目标卡；读取两字段保证一致性，只返回可编辑字段。
- **issue / cases**：分析与原始开发证据，包括已核实注入和选择关系；用卡正文及轨迹核对修复建议。
- **library_catalog / related_cards**：保留任务区别的上下文，不是额外修订目标。
- **variant / earlier_edits**：同计划已有候选；提出实质替代方案而非改写措辞，不能据此推断拒绝原因。
- **max_card_words**：包含冻结字段的组装整卡预算。

## 修订要求

1. 找出计划关联的具体措辞或缺失决策规则，区分内容缺失/误导与充分规则被忽略、未使用或执行不可靠。
2. 按下面的操作要求修订，保持操作和目标；单字段不足以完成有依据的修复时 skip。
3. 保留有效规则、证据依赖与先决条件；不加入案例答案、偶然限制或无关要求。
4. 核对组装后整卡与共享规范及用途/方法一致性；存在 earlier_edits 时提供有依据的实质不同修复，或 skip。

## 各操作要求

- **WHEN**：只返回完整替换 when_to_use。让题目、选项和视频元信息能识别支持的任务，必要时明确输入关系、主要任务和答案内容；不变的 strategy 必须已支持该范围。例如，指定时刻计数方法应描述该时刻数量，而非一段时间的事件总数。用途不包含执行指令或不可用观察条件。
- **STRATEGY**：只返回完整替换 strategy，保持冻结 when_to_use 的范围与先决条件。修复对应动作、指令、证据处理或完成条件，保留完整可执行过程；例如，把原样重复请求替换为针对争议区间和完成线索的请求。不能通过正文扩大适用范围，也不能把已有明确规则重复一遍并称作补齐。

## 阶段约束

- 只修一张卡的一个字段，不输出或改写冻结字段、ID、role、stages。
- 各案例使用自己的公开证据；参考答案说明差异，不证明未见视觉事实。
- 使用有效动作及输入/此前结果中的参数来源，保留题目标准及所需结果。
- 注入未知不证明策略缺陷；历史拒绝和相关成功不证明因果。
- edit 待后续评估，Gate/Test 明细不可用。

## 输出格式

仅返回符合操作特定 Schema 的 JSON 对象，不加 Markdown 围栏或额外文字：
- **status**：edit 或 skip。
- **summary**：字段修复及依据，或跳过原因。
- WHEN 的 **when_to_use** 或 STRATEGY 的 **strategy**：edit 为完整非空英文替换文本；skip 为 null。

只返回这三字段。JSON 字符串内换行用 \n 转义；不输出另一内容字段或目标 metadata。
